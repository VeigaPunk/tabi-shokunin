# RevC1EgressWindow — round 39 C1 review

## Finding — high: receipt can claim dual-surface coverage when one surface is absent

The implementation treats either readable surface as sufficient, and the frozen counter does not require both. In `scripts/playwright-firefox-egress-round39.mjs:116-127`, an empty `ss` result maps to `null`; `sampleSockets` at lines 218-226 accepts the sample if either surface is available and substitutes `{ticks:0, lines:0, nonLoopback:0, unavailable:true}` for the missing one. The driver only refuses when *both* are unavailable (lines 258-262). `/proc` similarly counts as available when either `/proc/net/tcp` or `tcp6` is readable (lines 194-200), so an unavailable family is silently omitted. In `.ufo/waves/round-39/counters/c1-egress-session-bound.mjs:110-118`, the counter checks sample count, duration, and zero `nonLoopback` totals, but never rejects per-sample unavailable/zero-tick surfaces. A receipt with one surface unavailable for every sample can therefore satisfy the purported two-surface predicate; final sweep's checks also accept the explicit zero-valued unavailable surface.

**Concrete falsification case (not run; live-browser item was not required):** execute the driver with `ss` unavailable on its inherited `PATH`, while `/proc/net/tcp{,6}` remains readable and the normal loopback fixture works. It will encode `ss.unavailable:true`, `ss.ticks:0`, and `ss.nonLoopback:0` while recording usable `/proc` observations. The frozen counter's referenced checks admit those values. A stricter deterministic receipt-level control can start from a valid v2 receipt, mark each run's `sockets.ss` and `finalSweep.ss` unavailable with zero counts, preserve the other fields, then evaluate with the frozen counter; expected result is erroneous predicate success if all other fields are valid. This disproves the contract without requiring external egress.

## Additional coverage gaps

- **Owned process set is frozen before navigation.** `ownedRoots` and `ownedTree` run once at lines 245-246, before the sampler starts (line 268) and before `newPage`/navigation (lines 277-286). The per-tick callback samples `rec.owned.tree` unchanged (line 270); no descendant refresh occurs. A Firefox child created after that snapshot, including one that owns a later TCP connection, is omitted from both surfaces. This contradicts the driver comment at lines 9-13 describing descendant enumeration once per sample tick. A concrete counterexample is a TCP-owning descendant spawned after `tree0` capture: its socket is absent from the observed PID set even while its parent remains in the tree.
- **Startup interval is unobserved.** Browser launch is followed by a 400 ms sleep, root discovery, and a preflight sample (lines 242-250); periodic sampling starts only afterward (lines 265-274). Preflight is not included in `rec.samples`, `sampleCount`, or coverage duration (`t0` is set after preflight, line 266). Any startup TCP connection opened and closed before the first periodic sample is unrecorded. Navigation startup is likewise not continuously sampled from process creation.
- **Sampling is point-in-time, not complete event capture.** A 100 ms interval with synchronous `ps`, `ss`, and `/proc` reads (lines 268-274, 81-87, 116-127, 194-215) cannot establish absence of a short-lived TCP socket wholly between samples. The one final sweep after close (lines 315-330) cannot recover such events.
- **TCP only, process tree only.** `ss -Htnp` and `/proc/net/tcp{,6}` (lines 116-118, 194-199) do not observe UDP/QUIC, and PID ancestry cannot cover socket activity delegated to an out-of-tree service/helper. The item asks about TCP; these remain explicit limits on broader browser egress claims.

## Evidence / method

Read the frozen claims at `.ufo/waves/round-39/claims.json` (C1 requires dual surfaces, startup/navigation sampling, and post-close sweep), frozen C1 counter, and the exact driver sections cited above. The `lsp` device was queried (`xd://lsp`) and returned `No such tool: xd://lsp`; semantic LSP references/diagnostics were unavailable, so this report relies on the direct frozen source text rather than grep-based semantic claims. No browser was launched and no counter was executed; the falsification case is a source-derived test proposal, not an observed runtime result.

VERDICT finding — one-surface-unavailable receipts can pass the dual-surface counter; process-tree snapshot and periodic sampling also leave egress coverage gaps.
