## 1. What the stateful fixture is — and what it is not

**State model (all server-side, all lane-authored):**

- **Session** — `GET /`, `/form`, `/result` mint a `tabi_sid` cookie when none is
  presented or the presented value is unknown. Any well-formed value is accepted:
  **no real auth** (there is nothing to authenticate against; a session exists
  only to carry state across visits). `Set-Cookie: tabi_sid=<16 lower-hex>;
  Path=/; HttpOnly; SameSite=Lax` — a browser-session cookie (no expiry
  attribute).
- **Visits** — counted on `/` only; the counter is server-side and rendered into
  the page (`data-visits`). This is the multi-visit subject.
- **One-time token** — minted per `/form` render (`secrets.token_hex(8)`; 16
  lower-hex), consumed exactly once by `POST /submit`. Second use → `409`.
- **Apply counter** — incremented by `POST /submit` when a fresh token is
  consumed. It is the non-idempotent resource.
- **Apply timing switch** — `?apply=pre` (consume + apply, *then* hold, then
  respond) vs `?apply=post` (hold first, apply after). `&guard=1` adds a
  socket-aware check before the deferred apply (`select` + `recv(MSG_PEEK)`
  `== b""`; `server.py:137-145`).
- **Ledger** — every write attempt is recorded (`write-ok` / `write-aborted`),
  every state transition is recorded (`session-mint`, `visit`, `token-mint`,
  `apply`, `apply-skipped`, `submit-refused`), in arrival order, tied to the
  session ordinal.

**Instrument boundary — what this is not:** not an auth study (no credentials
exist); the 409 is the *fixture's* refusal code, not a claim about real servers;
the token is a CSRF-*shaped* instrument, not a security analysis; a loopback 429
would never be a C6 datum (`external-class-fixture-v2.md` §8 stands); and the
`Range`/`Retry-After`-class rules of v2 are untouched here.

#!/usr/bin/env python3
"""TABI lane B8-1 fixture server v3 — stateful loopback fixture (lane-authored bytes).

Server-side state: sessions (cookie-shaped, no real auth), one-time tokens,
an apply counter, plus an ordered ledger. /__ledger is deterministic (no
timestamps, no random) so two cold runs of one cell can be byte-compared.

Routes (all loopback; Cache-Control: no-store on every instrument response):
  GET  /__ready                 quiet 204 readiness probe (never logged)
  GET  /__ledger                quiet instrument read: JSON server state
  GET  /                        index; mints a session cookie when absent; counts visits on /
  GET  /form                    form page; mints one one-time token per render
  POST /submit                  consumes the token; ?apply=pre|post&hold=MS&guard=1
                                -> 303 /result
  GET  /result                  shows counter + session visits
  POST /echo307                 -> 307 /echo307-target (method/body preservation arm)
  POST /echo307-target          200 JSON {method, bodyBytes}
  GET  /slow-hop1?hold=MS       302 -> /slow-hop2 after hold
  GET  /slow-hop2?hold=MS       302 -> /result after hold
  GET  /away                    plain page (navigation-abandon target)

Usage: server.py <port>
"""
import json
import re
import secrets
import select
import socket
import sys
import threading
import time
import urllib.parse
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

PORT = int(sys.argv[1])

LOCK = threading.Lock()
STATE = {
    "counter": 0,
    "tokens": {"minted": 0, "consumed": 0, "refused": 0},
    "token_table": {},   # token -> {"used": bool}
    "sessions": {},      # sid -> {"ordinal": int, "visits": int}
    "sessions_order": [],
    "events": [],
}
SID_RE = re.compile(r"^[0-9a-f]{16}$")


def ev(kind, **kw):
    STATE["events"].append({"seq": len(STATE["events"]) + 1, "kind": kind, **kw})


def ledger():
    return {
        "counter": STATE["counter"],
        "tokens": dict(STATE["tokens"]),
        "sessions": [
            {"ordinal": "s%d" % (i + 1), "visits": STATE["sessions"][sid]["visits"]}
            for i, sid in enumerate(STATE["sessions_order"])
        ],
        "events": [dict(e) for e in STATE["events"]],
    }


PAGE = """<!doctype html>
<html lang="en"><head><meta charset="utf-8"><title>%s</title>
<style>html,body{margin:0;padding:0;background:#fff;color:#111;font:16px/1.5 monospace}
#frame{width:800px;height:600px;box-sizing:border-box;padding:24px}
#state{background:#eef2ff}</style></head>
<body><div id="frame">%s</div></body></html>"""


class Handler(BaseHTTPRequestHandler):
    server_version = "tabi-fixture-v3/0.1"
    protocol_version = "HTTP/1.0"

    def log_message(self, fmt, *args):
        if getattr(self, "_quiet", False):
            return
        sys.stderr.write("%s - - [%s] %s\n" % (self.client_address[0], self.log_date_time_string(), fmt % args))

    # ---- plumbing -------------------------------------------------------

    def _emit(self, code, payload=b"", ctype="text/plain; charset=utf-8", headers=()):
        try:
            self.send_response(code)
            for k, v in headers:
                self.send_header(k, v)
            self.send_header("Content-Type", ctype)
            self.send_header("Content-Length", str(len(payload)))
            self.send_header("Cache-Control", "no-store")
            self.end_headers()
            self.wfile.write(payload)
            self.wfile.flush()
            if not getattr(self, "_quiet", False):
                with LOCK:
                    ev("write-ok", path=self.path.split("?", 1)[0])
        except (BrokenPipeError, ConnectionResetError):
            if not getattr(self, "_quiet", False):
                with LOCK:
                    ev("write-aborted", path=self.path.split("?", 1)[0])
                sys.stderr.write("== ABORTED response write (client closed): %s\n" % self.path)

    def _redirect(self, code, location):
        self._emit(code, b"", headers=(("Location", location),))

    def _send(self, code, body="", ctype="text/plain; charset=utf-8", headers=()):
        self._emit(code, body.encode("utf-8"), ctype=ctype, headers=headers)

    def _sid(self):
        raw = self.headers.get("Cookie") or ""
        for part in raw.split(";"):
            k, _, v = part.strip().partition("=")
            if k == "tabi_sid" and SID_RE.match(v):
                return v
        return None

    def _ensure_session(self, count_visit=False):
        sid = self._sid()
        cookie_state = "present" if sid else "absent"
        minted = False
        with LOCK:
            if sid is None or sid not in STATE["sessions"]:
                sid = secrets.token_hex(8)
                ordinal = len(STATE["sessions_order"]) + 1
                STATE["sessions"][sid] = {"ordinal": ordinal, "visits": 0}
                STATE["sessions_order"].append(sid)
                ev("session-mint", sid=ordinal, cookie=cookie_state)
                minted = True
            rec = STATE["sessions"][sid]
            if count_visit:
                rec["visits"] += 1
                ev("visit", sid=rec["ordinal"], cookie=cookie_state, visits=rec["visits"])
            ordinal = rec["ordinal"]
        return sid, ordinal, minted

    def _client_gone(self):
        """Socket-aware server variant: True when the peer already closed."""
        try:
            r, _, _ = select.select([self.connection], [], [], 0)
            if not r:
                return False
            return self.connection.recv(1, socket.MSG_PEEK) == b""
        except OSError:
            return True

    # ---- GET ------------------------------------------------------------

    def do_GET(self):
        parsed = urllib.parse.urlparse(self.path)
        path = parsed.path
        q = urllib.parse.parse_qs(parsed.query)
        if path == "/__ready":
            self._quiet = True
            self.send_response(204)
            self.send_header("Content-Length", "0")
            self.end_headers()
            return
        if path == "/__ledger":
            self._quiet = True
            with LOCK:
                payload = json.dumps(ledger()) + "\n"
            self._send(200, payload, ctype="application/json")
            return
        if path == "/":
            sid, _, minted = self._ensure_session(count_visit=True)
            with LOCK:
                visits = STATE["sessions"][sid]["visits"]
            headers = (("Set-Cookie", "tabi_sid=%s; Path=/; HttpOnly; SameSite=Lax" % sid),) if minted else ()
            body = PAGE % ("TABI-R8-1 index",
                           '<h1>TABI-R8-1 stateful fixture v3</h1>\n'
                           '<p id="visits" data-visits="%d">visits: %d</p>\n'
                           '<p><a id="form-link" href="/form">go to the form</a></p>\n'
                           '<p><a id="slow-link" href="/slow-hop1?hold=700">slow chain</a></p>' % (visits, visits))
            return self._send(200, body, ctype="text/html; charset=utf-8", headers=headers)
        if path == "/form":
            sid, _, minted = self._ensure_session(count_visit=False)
            token = secrets.token_hex(8)
            with LOCK:
                STATE["token_table"][token] = {"used": False}
                STATE["tokens"]["minted"] += 1
                ev("token-mint", sid=STATE["sessions"][sid]["ordinal"])
            headers = (("Set-Cookie", "tabi_sid=%s; Path=/; HttpOnly; SameSite=Lax" % sid),) if minted else ()
            body = PAGE % ("TABI-R8-1 form",
                           '<h1>submit</h1>\n'
                           '<form id="f" method="POST" action="/submit">\n'
                           '<input type="hidden" id="token" name="token" value="%s">\n'
                           '<input id="note" name="note" type="text" value="">\n'
                           '<button id="submit" type="submit">submit</button>\n'
                           '</form>' % token)
            return self._send(200, body, ctype="text/html; charset=utf-8", headers=headers)
        if path == "/result":
            sid, _, minted = self._ensure_session(count_visit=False)
            with LOCK:
                counter = STATE["counter"]
                visits = STATE["sessions"][sid]["visits"]
            headers = (("Set-Cookie", "tabi_sid=%s; Path=/; HttpOnly; SameSite=Lax" % sid),) if minted else ()
            body = PAGE % ("TABI-R8-1 result",
                           '<h1>result</h1>\n'
                           '<p id="counter" data-counter="%d">counter: %d</p>\n'
                           '<p id="visits" data-visits="%d">visits: %d</p>' % (counter, counter, visits, visits))
            return self._send(200, body, ctype="text/html; charset=utf-8", headers=headers)
        if path == "/slow-hop1":
            time.sleep(int((q.get("hold") or ["0"])[0]) / 1000)
            return self._redirect(302, "/slow-hop2?hold=%s" % (q.get("hold2") or ["0"])[0])
        if path == "/slow-hop2":
            time.sleep(int((q.get("hold") or ["0"])[0]) / 1000)
            return self._redirect(302, "/result")
        if path == "/away":
            return self._send(200, PAGE % ("TABI-R8-1 away", '<h1>away</h1>\n<p id="away">navigation moved on</p>'),
                              ctype="text/html; charset=utf-8")
        return self._send(404, "fixture endpoints only\n")

    # ---- POST -----------------------------------------------------------

    def do_POST(self):
        parsed = urllib.parse.urlparse(self.path)
        path = parsed.path
        q = urllib.parse.parse_qs(parsed.query)
        length = int(self.headers.get("Content-Length") or 0)
        body = self.rfile.read(length) if length else b""
        if path == "/submit":
            return self._submit(body, q)
        if path == "/echo307":
            return self._redirect(307, "/echo307-target")
        if path == "/echo307-target":
            return self._send(200, json.dumps({"method": self.command, "bodyBytes": len(body)}) + "\n",
                              ctype="application/json")
        return self._send(405, "fixture endpoints only\n")

    def _submit(self, body, q):
        fields = urllib.parse.parse_qs(body.decode("utf-8", "replace"))
        token = (fields.get("token") or [""])[0]
        apply_mode = (q.get("apply") or ["pre"])[0]
        hold_ms = int((q.get("hold") or ["0"])[0])
        guard = (q.get("guard") or ["0"])[0] == "1"
        sid = self._sid()
        with LOCK:
            ordinal = STATE["sessions"][sid]["ordinal"] if sid in STATE["sessions"] else None
            rec = STATE["token_table"].get(token)
            if token == "" or rec is None:
                STATE["tokens"]["refused"] += 1
                ev("submit-refused", reason="unknown-token", bodyBytes=len(body))
                ok = False
            elif rec["used"]:
                STATE["tokens"]["refused"] += 1
                ev("submit-refused", reason="token-consumed", bodyBytes=len(body))
                ok = False
            else:
                ok = True
                if apply_mode == "post":
                    deferred = True
                else:
                    deferred = False
                    rec["used"] = True
                    STATE["tokens"]["consumed"] += 1
                    STATE["counter"] += 1
                    ev("apply", sid=ordinal, bodyBytes=len(body), mode=apply_mode)
        if not ok:
            return self._send(409, "token refused\n")
        if hold_ms:
            time.sleep(hold_ms / 1000)
        if deferred:
            gone = self._client_gone() if guard else None
            with LOCK:
                if guard and gone:
                    ev("apply-skipped", sid=ordinal, reason="client-gone", bodyBytes=len(body))
                else:
                    rec["used"] = True
                    STATE["tokens"]["consumed"] += 1
                    STATE["counter"] += 1
                    ev("apply", sid=ordinal, bodyBytes=len(body), mode=apply_mode,
                       guard=("gone" if gone else "alive") if guard else "off")
        self._emit(303, b"redirecting\n", headers=(("Location", "/result"),))


if __name__ == "__main__":
    ThreadingHTTPServer(("127.0.0.1", PORT), Handler).serve_forever()

Four independent surfaces, all read on `multi-visit` (cold profile; browser) and
`curl-control` (jar; no browser). **No value is recorded anywhere** — length and
charset class only; the fixture's own values never leave the run artifacts.

| surface (producer) | visit | reading |
|---|---|---|
| `Set-Cookie` header (server) | 1 | `tabi_sid=<VALUE>; Path=/; HttpOnly; SameSite=Lax` — value 16 lower-hex (shape only) |
| CDP cookie store (`Network.getCookies`, browser) | after v1 / after v2 | 1 cookie: `{name: tabi_sid, valueLen: 16, valueClass: lower-hex, size: 24, domain: 127.0.0.1, path: /, session: true, expires: -1, httpOnly: true, secure: false, sameSite: "Lax"}` |
| page JS (`document.cookie`, browser) | after v1 / after v2 | `len 0`, `names []` — **HttpOnly delta: the cookie is in the store and invisible to page script** |
| curl jar (non-browser client) | end | `#HttpOnly_127.0.0.1 FALSE / FALSE 0 tabi_sid <16 lower-hex>` — the `#HttpOnly_` prefix and `expires=0` (session) survive in a non-browser store too |
| server ledger (server) | per request | session ordinal `s1`; `cookie=absent` then `cookie=present` — identity correlation lives here |

[inference, strong] The census can correlate client and server *without a value*
only because the server keeps its own ledger; on a real site no such surface
exists and any value-derived key (e.g. hashing the cookie) breaks the shape-only
rule. The pattern's honest limit is therefore: shape censuses are per-surface,
and cross-surface identity claims need the server's cooperation. Falsifier: a
run where the client-side census alone (name + length + attributes) distinguishes
two sessions — impossible here, since two sessions of this fixture have identical
shape by construction (only the value differs).

Two further shape facts measured, not assumed: the attribute set is *stable
across visits* (visit 2 carried no `Set-Cookie` line at all), and `size: 24`
equals `len("tabi_sid") + len(value) = 8 + 16` — the CDP `size` is computed from
name+value, a useful check that the store saw the same value the server minted
without either value being read.

## 6. Measured — the state-changing step (round-7 L1a–L1c)

All four cells below ran N=2 cold reps; every value quoted is rep-invariant
(`verify.py` digests identical, §9).

**L1a — POST form submit with a request body (`post-form`).** A real form submit
(fill + `requestSubmit()`, navigation POST, not fetch): server line
`"POST /submit HTTP/1.1" 303 -`; ledger `apply … bodyBytes: 44, mode: "pre"`
(44 = url-encoded `token=<16 hex>&note=cell%3Dpost-form`); the 303 is followed by
`GET /result` `200`; the result page renders `data-counter="1"`,
`data-visits="1"`. **The POST's own status (303) exists at two surfaces only —
the server log and the CDP `wire` event — never at the page's fetch/document
status, which reports the terminus (200).**

**L1b — redirect-after-POST, 303 vs 307 (`post-303` vs `post-307`).** One factor:
the redirect status.

| reading | `post-303` (scripted fetch) | `post-307` (scripted fetch) |
|---|---|---|
| chain (wire events, in order) | `POST /submit` -> 303; `GET /result` -> 200 | `POST /echo307` -> 307; `POST /echo307-target` -> 200 |
| method at the terminus | changed to GET (server log: `GET /result`) | **preserved POST** (server log: two POST lines; body `k=v&n=12` = 8 B delivered) |
| client object | `{status: 200, redirected: true, finalUrl: /result}` | `{status: 200, redirected: true, finalUrl: /echo307-target, text: "{\"method\": \"POST\", \"bodyBytes\": 8}"}` |
| server state | `counter 0 -> 1`, token consumed | `counter 0`, no token involved |

**L1c — one-time token, minted per render, consumed once (`token-once`).** Fresh
token: `{200, redirected, finalUrl /result}` + ledger `apply`. Same token again
(no re-render): `{409, redirected: false, finalUrl /submit}` + ledger
`submit-refused reason: token-consumed`; `counter` stays `1`; tokens
`{minted: 1, consumed: 1, refused: 1}`. The refusal is a *wire + server* fact; the
client sees only the 409 (no redirect followed).

**Duplicate submission, two parallel identical submits on one token
(`dup-submit`).** `Promise.all` of two fetches with the same token and body:
outcomes `[200-redirected, 409]` in both reps, `counter: 1`, tokens
`{1, 1, 1}`. **The loser's refusal and the winner's response write interleave
differently across cold reps** — rep 1:
`apply -> submit-refused -> write-ok(/submit) -> write-ok(/submit)`; rep 2:
`apply -> write-ok(/submit) -> submit-refused -> write-ok(/submit)` — while the
server log order (`303` line then `409` line) and every outcome are identical.
This is the matrix's one *deliberate* non-determinism class, and it is on the
server's own event ledger, not on the client.

## 7. Measured — the non-idempotent step under failure (round-8 L1)

### 7.1 Interrupt mid-POST — three arms, one factor each

Client pattern: scripted `fetch` with `AbortController`, abort at 150 ms
(§2 excerpt); server hold 700 ms; driver reads the ledger ≥1.3 s later. All three
arms, both reps: client `AbortError` at 150/151 ms; CDP `failed
net::ERR_ABORTED, canceled: true`; **no response event on any client surface**;
server log carries the applied status followed by the abort marker:

```
"POST /submit?apply=pre&hold=700 HTTP/1.1" 303 -
== ABORTED response write (client closed): /submit?apply=pre&hold=700
```

| arm (the one factor) | ledger after | token | server state | decided by |
|---|---|---|---|---|
| `interrupt-pre` (apply **before** hold) | `apply(mode=pre, bodyBytes=41)` + `write-aborted(/submit)` | consumed | `counter 1` | server applied before the client left; the response was written into a closed socket |
| `interrupt-post` (apply **after** hold; naive server) | `apply(mode=post, guard=off, bodyBytes=42)` + `write-aborted(/submit)` | consumed | `counter 1` | server applied **~550 ms after the client had already left**, because nothing told it the client was gone |
| `interrupt-post-guard` (same, `guard=1`) | `apply-skipped(reason=client-gone, bodyBytes=48)` + `write-aborted(/submit)` | **not consumed** (`consumed: 0`) | `counter 0` | the socket check decided; the client cannot distinguish this arm from the other two |

**The finding that carries:** an abandoned non-idempotent step has *no
client-side trace of its outcome* in any of the three arms, and its actual
outcome is a **server-architecture fact**: applied-before / applied-anyway /
skipped are three different server states behind three identical client
observations (abort + nothing). This is the rung D3/D4 claim ("an abandoned
request has a server 200 line no client ever received",
`network-evidence-rung.md` :271-282) extended: the server line can also exist for
work the client left *before it was even computed*.

### 7.2 Interrupt between redirect hops — two fetch arms

| arm (the one factor) | wire chain | server log | ledger | replay |
|---|---|---|---|---|
| `hop-abort-1` (abort during hop 1's hold) | `GET /slow-hop1?hold=700&hold2=0` -> failed `ERR_ABORTED` (no status delivered) | hop1 line (302) + abort marker; **hop2 absent** (`grep -c ' /slow-hop2'` -> 0) | `write-aborted(/slow-hop1)` | direct `GET /result` -> 200, `counter 0` |
| `hop-abort-2` (abort during hop 2's hold) | hop1 -> `wire 302` **delivered**; `GET /slow-hop2?hold=700` -> failed `ERR_ABORTED` | hop1 302, hop2 302 + abort marker; **`/result` absent** | `write-ok(/slow-hop1)`, `write-aborted(/slow-hop2)` | direct `GET /result` -> 200, `counter 0` |

The chain stops exactly at the hop whose response is in flight: nothing after the
abort is requested (proved by the server log counts), and the terminus stays
directly replayable with the state unchanged.

### 7.3 Navigation-level interruption — the negative result (kept)

Two attempts, both at 150 ms into a navigation whose first response is held
700 ms; both **failed to interrupt**, and the failure is the datum:

- `nav-supersede` (and the superseded first-design runs kept in
  `runs/abort-hop1/`, `runs/abort-hop2/`): a second `Page.navigate` issued at
  150 ms did not cancel the first navigation. Measured order (rep1): hop1
  request at 41 ms, full chain (`hop1 302 -> hop2 302 -> /result 200`) completes
  at ~745 ms, **`/away` is requested only at ~897 ms** and commits. The page
  ends on `/away`; the server chain ran to completion; no abort marker.
- `nav-stop`: `Page.stopLoading` at 150 ms — the chain completed (all three
  writes `write-ok`), the page committed `/result`; no abort marker.

[observation] with a held response in flight, neither CDP command produced a
cancellation at this timing; [inference] CDP-initiated navigations are serialized
behind the pending navigation and `stopLoading` does not cancel a provisional
browser-initiated navigation — mechanism **unexamined** (U4). The contrast with
7.1/7.2 is the operative rule: **client-script aborts cancel; CDP navigation
commands at this timing did not** — 10/10 abort-marked runs came from
`AbortController`, 0/8 from navigation commands (the 4 matrix runs plus the 4
superseded-design runs).

## 9. The replay contract, and how the cells were verified

**Replay contract for the non-idempotent step (as exercised here).**

1. **Fresh state root per run** — a new server process; otherwise `counter` and
   the token table diverge by construction. Cross-rep comparisons use per-run
   ledgers (`ledger-after.json`), never a shared server.
2. **Same-cell rerun byte-identity holds on derived facts**: `ledger-after.json`
   byte-identical in 13/14 cells (the exception is `dup-submit`'s event order,
   §6); all 20 PNG captures byte-identical across reps; normalized server logs
   (timestamps stripped) identical 14/14; full event-chain digests identical
   13/13 browser cells with timing fields stripped.
3. **Byte-identity does not hold on**: raw timings (abort at 150 vs 151 ms;
   capture offsets), CDP's **inter-kind event arrival order** — `wire` vs `resp`
   vs `req` ordering inside one requestId flips between reps (first seen in
   `post-303`; the reason `verify.py` compares kind-separated sequences), server
   log timestamps, PIDs.
4. **A replayed token after an interrupt**: `interrupt-pre`/`interrupt-post`
   consume the token — replaying the same token would be refused (409) and the
   state stays; `interrupt-post-guard` does **not** consume it — a replay with
   the same token would still be accepted and apply `counter 1` [the replay
   itself was **not** run; unknown U5].
5. **No client surface reports the applied-but-unreceived change** — the
   abandoned runs' fetch/DOM/network artifacts show only the abort; the
   authoritative record is the server's log + ledger (this is why the ledger is
   the state surface and the DOM is not).

## 10. Rules added (each with its falsifier)

- **R1 — Server-side state is the ground truth; the DOM is a rendering of it.**
  The multi-visit counter and the apply counter are only comparable through the
  server ledger; a screenshot or DOM reading alone cannot prove state.
  *Falsifier:* a run where the DOM reading disagrees with the ledger and the DOM
  is right (would require the fixture to render something it did not store).
- **R2 — A cookie census is per-surface and shape-only.** Four surfaces were read
  (server header; CDP store; page JS; curl jar) and they disagree by design:
  HttpOnly makes the value invisible to page JS while the store and the jar hold
  it. *Falsifier:* a page-JS reading that shows a `tabi_sid` value (would need a
  non-HttpOnly cookie).
- **R3 — For a followed redirect-after-POST, the client-side status is the
  terminus; the POST's own status lives at `wire` + server.** *Falsifier:* a
  client surface reporting the intermediate 303/307 for the same request — not
  observed in 6/6 redirect cells.
- **R4 — One-time token semantics are server-decided; the client sees a status
  code.** A replayed token produced 409 and no state change; the *rule* is only
  readable server-side. *Falsifier:* a replay that mutates state (would show a
  lost-update; not observed in `token-once`/`dup-submit`, 4/4 runs).
- **R5 — An abandoned in-flight POST may apply before, during, or after the
  client's departure; the client cannot tell.** Three arms, identical client
  observations, three server outcomes (§7.1). *Falsifier:* a client-side artifact
  distinguishing the three arms.
- **R6 — Whether an abandoned step applies is a server-architecture fact, not a
  protocol fact.** The same bytes and the same abort yield `counter 1` or
  `counter 0` depending on a socket check. *Falsifier:* a run where the guard
  reads "alive" for a client that has already closed the connection.
- **R7 — A client abort stops a redirect chain at the hop in flight; earlier hops
  may already have been delivered.** hop-abort-1 stopped before hop2; hop-abort-2
  stopped at hop2 after hop1's 302 was delivered and followed. *Falsifier:* a run
  where a hop after the abort point is requested (server log shows it).
- **R8 — A 303/307 hop's response that no client receives still has a server
  line.** The abort marker + the status line are the only trace; the terminus
  remains replayable with state unchanged. *Falsifier:* an aborted hop that
  leaves state changed (would indicate apply-before-hold semantics on a GET
  chain — this fixture's chain never applies).
- **R9 — Duplicate submission: one wins, one is refused, and the server's
  internal event order is not reproducible across cold runs while the observable
  outcome is.** *Falsifier:* a rep where both apply, or where the winner/loser
  statuses differ across reps.
- **R10 — Client-script aborts cancel; CDP navigation commands at this timing did
  not.** 10/10 `AbortController` runs produced abort markers; 0/8 navigation-command
  runs did (4 matrix + 4 superseded-design), and the chain completed server-side. *Falsifier:* a `stopLoading`/
  second-`navigate` run that cancels the held navigation (the mechanism is
  unexamined, U4 — do not over-generalize R10 beyond this fixture/timing).
