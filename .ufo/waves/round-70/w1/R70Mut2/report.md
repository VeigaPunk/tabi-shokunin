## Method

1. `setup.sh` copied the lane `scripts/` + the two evidence receipts + the committed forger into
   `/fast/scratch/hyaku/tabi-r70/R70Mut2/s/`, and built three probe trees: `d/` (counter swapped for an
   exit-9 stub), `e/` (r70 evidence receipt removed), `t/` (byte-identical and tampered copies of the frozen
   r69 driver). All five pins the verifier enforces were asserted before use.
2. 17 mutants were generated by single-line replacement of the **scratch copy**, each diff verified to be
   exactly one removed + one added line (`mutants.json` records the diff and mutant sha256). Mutants live in
   `s/scripts/mut-*.mjs` (or `d/`, `e/` for the probes), so the verifier's `LANE`
   resolves to the scratch copy: witness `witness/lane-resolution-M01.json` shows the executed driver is the
   scratch forger and `counterSha256` is the pinned r69 counter.
3. Each mutant was run against one detector: a committed control invocation from
   `.ufo/waves/round-70/controls/run-controls.sh` where one applies, otherwise a probe that reproduces the
   control's shape (noted in the table). Kill test = the frozen control's own expectation (exit equality and
   every expected finding id present — the semantics of `controls/evaluate-controls.mjs`). Every detector
   was first run on pristine bytes (`pristine` row), then on the mutant, then on restored pristine bytes.
   **All 12 baselines held and all 12 restored runs held; no mutant is inconclusive.** Results:
   `fast.json`, `live.json`; witness receipts in `witness/`.

## Survivor analysis

The verdict-bearing predicate is the exit code (`0` = pass, `1` = evaluated false, `2` = refusal, `4` = every
check held but a control override was used). Both survivors are exit-equivalent on counter-clean receipts:

* **M16** removes the click-detail element from the `synthtap-r70` fingerprint (line 83). The tap counter
  already pins exactly that value: `check-synthtap-r70.mjs:111` requires
  `canon(clickDetails) === canon(want.details)` per leg, and `:102,109` pin the event sequence the rest of the
  fingerprint records. A receipt that passes the pinned counter cannot differ in the dropped element, so the
  weakened fingerprint compares equal for every counter-clean pair; the mutant cannot flip a verdict. The
  committed battery therefore has no kill for it, and none is constructible without a counter weakness.
* **M17** forces `agreement.evidence = true` (line 185), dropping the `evidence-mismatch` finding. That
  finding is only observable on receipts that already fail the pinned counter. It did change the observed
  finding set of the degenerate control (`witness/degenerate-pristine-run-a.json` vs the M17 run: `evidence-mismatch`
  present vs absent), but
  the control's expectation is exit 1 + `{counter-a, counter-b}`, so the committed kill rule still holds.
  For the r69 profile every fingerprint element is itself counter-pinned (`check-synthscroll-r69.mjs:77-101`:
  leg order, scrollYBefore/scrollY, wheel sum, wheel presence, pointer/touch counts per class, scrollend
  presence), so a counter-clean live/evidence pair can never disagree. `evidence-mismatch` and
  `cross-run-mismatch` are defense-in-depth, not verdict-bearing, and no committed control asserts either id.

Both are coverage findings about the battery, not a licence to change the frozen contract: a future battery
that wants these checks to carry weight would need a counter-clean receipt pair that differs in a
fingerprint-only field — which the pinned counters make impossible by construction, so the checks can only
fire on receipts that are already red.

## Other observations (no contract change proposed)

1. **Strongest escapes are the digest/counter-pin family (M01–M04).** A forged receipt that claims the frozen
   driver digest (`witness/rewrite-full-lying-run-a.json` claims `13ea…` while the executed binary is the
   forger `9c2a…`) makes the verifier return exit 4 with **no findings**. Under the frozen predicate that is
   still not a pass (`pinSource: override`), so the scored claim is not endangered by any one of these
   mutants; M14 or M15 alone converts such a run to exit 0, and M13 does so for `--no-run`. A caller that
   keys on exit code rather than `predicate && pinSource === 'frozen'` would treat M13/M14/M15 output as
   success.
2. **No committed control exercises the counter-pin refusal.** M11 needed a purpose-built tree with the
   pinned r69 counter replaced by an exit-9 stub (`d/`). Pristine refuses at exit 2 before executing anything;
   the mutant proceeds and the exit-9 counter is accepted into the finding list.
3. **The committed `scratch-too-long` control is expensive to reuse under mutation.** With a real driver and
   an over-long scratch path, the verifier's own comment (lines 127–132) says Chromium dies and the pinned r69
   driver then waits 240 s per run (~2×240 s). The probe therefore uses the forger (which does not launch a
   browser) with a 155-byte singleton path; the predicate under test (guard fires before any launch) is
   identical.
4. **The `tap-no-evidence` probe reproduces the committed `c1/donothing-live-no-evidence` expectation**
   (exit 1 + `evidence-counter`), but the current tree has the r70 evidence receipt, so the committed
   control's recorded output (which also showed `evidence-unmeasurable`) was produced when that file was
   absent. The expectation still holds in both environments; only the recorded finding list differs.
