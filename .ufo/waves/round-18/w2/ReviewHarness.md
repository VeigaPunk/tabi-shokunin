## F2 — LOW — watchdog prints `run_timeout` and forces exit 2 even when its abort was a no-op during main-initiated cleanup

- `scripts/webmcp-invoke-round18.mjs:2798-2812`: the watchdog callback prints `WEBMCP_INVOKE_ERROR {"code":"run_timeout",…}` whenever `abortState` is null, then calls `cleanup()`. But `markAborted` (`:191-196`) returns false when `shutdownStarted` is already true and `kind !== 'signal'` — i.e. when main's normal-end `await cleanup()` (`:2536`) is still in flight at t = 420 s. In that interleaving: spurious `run_timeout` on stderr; watchdog's `.then` sets `process.exitCode = 2` (`:2806`) but main's continuation and `main().then(code ⇒ process.exitCode = code)` (`:2818-2820`) are queued after it, so the final exit code is the receipt's verdict code (0/1) while stderr claims a timeout and `reportAbortedRun()` silently no-ops. Condition: teardown taking >420 s−run-time (slow disk/loaded host); rare but produces a contradictory transcript. Fix: gate the print and the exit-2 forcing on `markAborted(…)` returning true.

## F3 — LOW — `probePortClosed` labels a timeout as `refused: true`, and `stopProofs` counts it as closure proof

- `scripts/webmcp-invoke-round18.mjs:772-784`: `req.on('timeout', … resolvePromise({ refused: true, reason: 'timeout' }))`. A timeout is not a refusal — a hung/dropped port would satisfy `serverPortProbe.refused === true` in `stopProofs` (`:2584`) and `closure.everyStopProof`. The receipt keeps `reason`, but the boolean claim is wrong-headed for a stop proof. Local loopback makes ECONNREFUSED the expected path (error branch `:783` sets `refused: true` correctly via `error.code`), so impact is low. Fix: distinct field (e.g. `closed: true` only on ECONNREFUSED/ECONNRESET-style errors) or `refused: false` on timeout.

## F5 — LOW — unbounded close paths can hang cleanup indefinitely on a wedged browser

## F6 — INFO — `closeCase` masks a crash landing in the `page.isClosed()` TOCTOU window

- `scripts/webmcp-invoke-round18.mjs:1235-1243`: `closeCase` polls `opened.page.isClosed()` and then sets `intentionalClose = true` before `page.close()`. If the fixture page dies unexpectedly in the window between the last operation and this poll — before Playwright dispatches the page `close` event — the subsequent event is masked as intentional (`:1199-1205` checks the flag). Self-heals on the next browser-closed operation (`isBrowserClosedError`, `:199-203`, matches Playwright's "Target page, context or browser has been closed" on the next call); only an abort arriving exactly after the last case's completion would be misclassified. Informational; an event-driven "case completed" flag would remove the window.
