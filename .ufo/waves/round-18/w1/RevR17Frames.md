# Round-17 CDP recorder reconstruction

## Reconstructed contract

`connectRawCdp` opens one WebSocket to the page target for each case/control. On every incoming WebSocket message it parses `event.data` as JSON (falling back to `{raw: String(event.data)}`), records it as `dir: "in"`, and matches any non-null `frame.id` to a pending command. Every record is `{seq, dir, atMs, frame}`; `seq` is a per-socket incrementing sequence and `atMs` is `Date.now() - t0` (harness `scripts/webmcp-invoke-round17.mjs:506-529`).

Outgoing commands allocate a per-socket integer ID starting at 1, form `{id, method, params}`, record it before `ws.send(JSON.stringify(frame))`, and retain the full reply in the incoming record. Success resolves to `reply.result`; a protocol failure rejects with both `error.protocolError = reply.error` and `error.reply = reply`. The request times out after 10 seconds (`scripts/webmcp-invoke-round17.mjs:532-559`). This gives the recorder the raw JSON protocol envelope and socket-order sequence, not a byte-level WebSocket capture: received data is parsed at lines 518-525 and outgoing data is JSON-stringified at 553-554.

For cases and controls, `caseStart` is the current record-array length immediately after attach and before `Page.enable`, `WebMCP.enable` (when enabled), and `Page.getFrameTree`; therefore the stored per-case slice includes those setup commands and their replies (`scripts/webmcp-invoke-round17.mjs:871-885,936-944`). Case records store the slice as `cdp.frames`, plus the WebMCP-only `events`, `eventLog` (`seq`, `atMs`, `method`, `params`), and flattened `toolsAdded` projections (`scripts/webmcp-invoke-round17.mjs:893-908`). Controls store their slice as `cdp.frames` (`:945-955`). The receipt's `rawPayloadNote` calls them “Verbatim CDP JSON frames” (`:893-898`), but the implementation retains parsed JSON objects, not original WebSocket frame bytes or original JSON text.

The concurrent-ID case depends on both `WebMCP.invokeTool` outgoing records preceding the first `WebMCP.toolResponded` event (`scripts/webmcp-invoke-round17.mjs:1433-1458`). Separately, the domain-disabled control predicate requires `invoke.error.code === -32601` (`:1865-1879`). Predicate digests are SHA-256 of `predicate.toString()` (`:791-805`, controls `:945-952`).

## Exact CDPSession mapping specification

Playwright 1.64.0's API documents `context.newCDPSession(page)`, `session.send(method, params)`, and a catch-all `session.on('event', ({method, params}) => ...)` for every CDP event (`playwright-core/types/types.d.ts:18383-18448`; installed package version `playwright-core/package.json:1-4`). Round-18's plan explicitly selects `context.newCDPSession(page)` and pipe CDP instead of a DevTools TCP port (`.ufo/waves/round-18/PLAN.md:27-35`).

## Receipt fields the r17 counter does and does not depend on

The counter reads the receipt verdict and producer digest; requires the runtime Chromium executable SHA-256 and zero external loopback requests; checks cases/controls, unique IDs, pass status, fixture filenames/digests, predicate digests, summary totals/case-set fields, and run `pid`, non-empty `argv` or `effectiveArgv`, and `gone:true` (`.ufo/waves/round-17/measure-c2.mjs:475-503,505-600,634-645`). The required case/control lists and three distinct fixture cases are declared at `:92-114,603-613`. Those receipt contracts are independent of the CDP transport and must remain unchanged for a compatible receipt. The counter does not test `schema` in its evaluator (`:475-495`), nor does it correlate a response ID with its request or validate any raw-frame count.

## Divergence and confidence

Last-known-good invariant: R17 records parsed protocol messages at the WebSocket boundary, before send and on message arrival, with the request's actual CDP ID, full reply/error envelope, and monotonically increasing socket sequence (`scripts/webmcp-invoke-round17.mjs:513-559`). CDPSession retains command results and event method/params, but removes the transport boundary; request/reply IDs are not exposed, successful reply envelopes must be synthesized, and numeric protocol error codes are lost. Thus a recorder can preserve the semantic WebMCP event evidence and predicate digests, but cannot preserve the raw-error evidence required by the existing disabled-domain predicate/counter without changing that contract. This is why the verdict is `ISSUES`, not a claim of drop-in equivalence.

Confidence: high for the receipt and counter behavior, based on direct reads of both source files and Playwright 1.64.0 API/implementation source; no browser run or counter execution was performed. The LSP device is not mounted (`read xd://lsp` returned “No such tool”), so no LSP semantic query was available; grep was used for line discovery only, with claims grounded in the source reads.
