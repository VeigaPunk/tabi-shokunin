## Findings by severity

### F1 (high) — after-window lower edge is unbounded and the navigation window is selected by wall time, so a coherent forgery widens the semantic after-window across the action boundary

Counterexample (exact, over retained `na-native-submit.json` + receipt row): change receipt `after.windowMs` 503 → 3000, so `after.start = 1792590710686 − 3000 = 1792590707686`, and mirror-coherently set receipt `after.navigations = [initialLoadNav, landingNav]` (initial-load `Page.frameNavigated` is frames seq3 `at=1792590709922`, landing is seq15 `at=1792590710190`). Old counter, L138: `3000≥500` ✓, `end−start=3000` ✓, `end===post.at` ✓, `after.start(7686)≤action.at(10183)` ✓ — no `window_mismatch`. L139 mirror: `9922≥7686 && seq3<17` → initial-load nav now inside `c.after.navigations` ✓ — no `summary_mismatch`. L136/L118 untouched. Result: exit0 clean, count12, with the receipt claiming the pre-invoke page-load navigation is an after-action navigation — precisely the distinction native-submit semantics (landing vs initial load, old-document submits null) exists to protect. The structural measure admits all-silent synthetic cases; this shows it also admits time-window-widening coherent ones.

Stable finding expectation (new oracle, contract-exported ids): `semantic_timing` (detail: window not pinned / lower edge unbounded) and `semantic_navigation` (navigation outside the after-window seq range). verdict failed, exit1, value0.

Bounded preserving positive: pin every case's `preAction.{start,end,windowMs}` and `after.{start,end,windowMs}` by exact equality in `semantic-expectations.json` to the independent retained values (na-pending pre 254 / after 503; na-delayed after exactly 755; na-click 252/547; na-requestsubmit 253/503; na-native-submit 253/503; na-reset 252/503; na-remove 253/503; na-reject 253/502; na-throw 253/502; na-invalid-submit 252/504; auto-positive 253/501; auto-invalid 253/501). Select after-window navigations purely by transcript order: `completedSeq < f.seq < postSeq` (native-submit → exactly seq15 landing; initial-load seq3 excluded by sequence, no wall-time test needed). Retained ground passes all pins.

### F2 (high) — action order must come from frame seq; wall-timestamp comparisons are false-positive and false-negative unsound on the retained ground itself

Counterexample A (false positive, real data): any new `semantic_delayed` check that infers "response released before response" via strict `response.at > release.at` fails the retained `na-delayed.json`, where release seq16 and `WebMCP.toolResponded` seq17 share `at=1792590715100` exactly (and seq15/16 share it too). Strict `>` on wall time rejects genuine ground; the L118-style non-strict monotonicity is the only sound timestamp relation.
Counterexample B (false negative, forged): place the `toolResponded` event at seq before the release frame but stamp both `at=1792590715100`; any `response.at >= release.at` design passes a response-before-release case — the exact defect AttackDelayed is assigned to catch ("response before release … must fail") is only catchable via seq: `release.seq < response.seq`.

Stable finding expectation: `semantic_delayed` fires when the seq chain is violated (release.seq ≥ response.seq, or `delayed-before-release` observation not strictly between action-complete and release, or its pageState `formActive !== true`); order predicates never compare `at` for strictness.

Bounded preserving positive: na-delayed pins the seq chain 9(invoke)<11(toolInvoked)<12(pre)<13(action)<14(action-complete)<15(delayed-before-release, formActive true)<16(release)<17(toolResponded)<18(post); duration `response.at − release.at` gets a finite upper cap only (observed 0 ms; lower bound must be 0 — any positive lower bound is unsound under millisecond granularity and would fail retained ground), plus the exact window pin `after.windowMs = 755` from F1. Same non-strict-`at`-only rule for the generic L136 chain (real na-pending seq12/13/14 all tie at 1792590707335).

### F3 (medium) — "pending" is finite only if the window is pinned and the whole trail is response-free; seq-scoped pending checks admit late-response forgeries

Counterexample (exact, over retained `na-pending.json`): append a `WebMCP.toolResponded` (Completed) at seq16–17 after the post marker (seq15 `at=1792590707838`), timestamps monotone. Old counter L139 mirrors `events.filter(f=>f.seq<post?.seq)` → still `[]` ✓; L138 unchanged ✓; exit0 clean — a case whose actual semantics are "Completed ≈2.5 s after action" is counted as the finite-pending case. Separately, unpinning the window (windowMs → 5000, post marker moved later, still coherent) re-labels the same ground as a 5-second pending claim; both defeat "pending finite" as an explicit semantic.
Stable finding expectation: `semantic_status` for na-pending requires zero `WebMCP.toolResponded` events carrying the invocationId across the entire frame array (not only `seq<postSeq`), plus `semantic_timing` exact pin `after.windowMs = 503` (and `preAction.responseCount = 0`, `preAction.windowMs = 254`).
Bounded preserving positive: retained na-pending raw satisfies both (whole 15-frame trail has no toolResponded; window 254/503) — the positive is preserved, the forgery is not.

### F4 (medium, debt side) — the chronology classifier must not classify "reviewed before/after acquisition" from wall timestamps alone

BuildDebt's specified trigger "review-return timestamp versus artifact acquisition start; acquisition-after-return reports `review_scope_gap`" compares timestamps from two clock domains. The historical debt itself proves the hazard: round21-closure records W1 returns captured 13:15:40Z *before* four seats' final exits (13:19:45Z) — a return timestamp can precede the seat's own terminal event by minutes — and W2 exit 13:45:46Z precedes returns 13:49:02Z. Timestamp sign flips depending on which latency dominates; classification must not.
Counterexample: input event list where `reviewReturn.ts = 13:15:40Z`, `finalExit.ts = 13:19:45Z`, `acquisitionStart.ts = 13:17:00Z` (all real-shaped). A timestamp-only rule reports `acquisition-after-return` → `review_scope_gap` even though `reviewedProducerDigest === acquiredProducerDigest` at the acquired Git revision — the reviewer demonstrably read the exact final bytes. Conversely, equal digests with "correct-looking" timestamps must never upgrade a digest-mismatch case to final-reviewed.
Stable finding expectation: digest identity is the sole basis for any final-reviewed classification (`revision_input` binds both digests to exact Git blobs at a full 40-hex revision, shell-free isolated Git env); digest mismatch → `review_scope_gap` regardless of timestamps; timestamp agreement is corroboration only, reported as an observation field, never decisive. Events are ordered by their position in the provided event list; the classifier never re-sorts by timestamp, and missing/abbreviated history yields exit2 could-not-evaluate (unresolved), never quiescence, completeness, or a wall-clock inference — matching `no quiescence certification` and `preserve unknown full history`, and CriticRetrospect's boundary (final statuses cannot retroactively certify wake completeness). Exact unresolved-finding id is BuildDebt's to name; only `review_scope_gap` is fixed by the assignment.
Bounded preserving positive: W1-shaped input with equal digests classifies final-reviewed-per-digest with the timestamp anomaly explicitly reported (ordering: timestamp-ambiguous); W2-shaped input (exit before returns) classifies identically on digests — both historical cases stay green without certifying byte-review beyond the digest, and append-only correction (ScribeDebt) records the W1-before-exits / W2-before-finalization facts without rewriting history.
