## Findings (ordered by severity)

### F1 — HIGH (C2 authentication scope; contract violation) — snapshot authentication is bound to default paths, not evaluated bytes

Evidence (HEAD):
- `scripts/check-aria-metadata.mjs` `verifySnapshot()` (871–925) takes no arguments and hashes only `DEFAULT_RECEIPT`, `DEFAULT_PIN`, manifest, spec, config, producer, and the one anchored worker (874–879).
- `runCheck` (1385–1386), `runDerive` (1617–1618), and `runWitnessMirrors` (1915–1916) call `verifySnapshot()` and then evaluate caller-supplied `receiptPathText`/`pinPathText` via `prepareContext`.
- `parseArguments` (3078–3143) accepts `--receipt` and `--pin` in check mode (defaults 3081–3082). `resolveCheckInput` (3033–3064) takes the receipt path from a sidecar's `original.receipt.path`/`original.pin.path`, and for a non-sidecar `--check <file>` uses that file as the receipt with `DEFAULT_PIN`.
- `evaluateAnchors` (826–856): byte comparison to `ANCHORS.receiptSha256`/`ANCHORS.pinSha256` happens only when the path is canonical (828–829, 830–833). The pair/binding checks run only under `if (canonicalReceipt || canonicalPin)` (846–852). With both paths non-canonical, no receipt or pin byte is compared to an anchor, and `R14-ARIA-ANCHOR-01` passes by construction.
- `evaluatePin` (~793–824): pin identity is checked only against the receipt's self-declared `runtime.pinned.pinSha256` (808–810) and a `pinPath` string (811). No anchor.
- `deriveNode` (524–552) takes the Node floor from the input pin (`pin.node.minimumMajor`, 527, 530, 536). `R14-ARIA-NODE-MINIMUM-01` (571–576) therefore inherits the floor from whichever pin file was supplied. `[INFERENCE]` A non-canonical pin with `minimumMajor: 0` would satisfy the floor for any observed Node major. This is source-derived only; not executed.
- The committed fixtures encode the non-canonical acceptance:
  - `sidecar-valid-accepted` (id at line 174; args `--receipt @receipt-old --pin @pin --sidecar @sidecar-valid`, lines ~148–156) expects exit 0 clean.
  - `sidecar-auto-detect-check-input` (id at line 193) expects exit 0 clean.
  - `receipt-old` is generated by `fixtureReceipt({ summaryListeningAfter: true, pinSha256 })` (HEAD 2365–2368). Its sha `d1a4ce85…` is not `ANCHORS.receiptSha256` (`b458b351…`, re-verified against the real `corpus/evidence/round-13/aria/receipt.json`, 97073 bytes).
- Consequence: `--check`, `--derive`, and `--witness-mirrors` can return clean/accepted for caller-selected, unanchored receipt+pin pairs. Authentic-byte tampering at a non-default path is never classified `snapshot_tampered`/exit 2. This contradicts `corpus/lessons/round-15.md` line 10 ("changed authenticated snapshot bytes yield `snapshot_tampered`/exit2 rather than a semantic verdict") and the SKILL.md gate row ("committed source/snapshot digest no longer matches → exit2", ~line 1781). The lesson's scope is not stated, and the CLI does not separate fixture mode from production.

Bounded correction (L1 chooses):
1. In production check mode, refuse any receipt/pin path other than the canonical pair with exit 2 (new reason, e.g. `input_not_canonical`, or reuse `snapshot_unavailable`). Make `resolveCheckInput` ignore sidecar-declared paths unless they are canonical.
2. Move non-canonical mkdtemp fixtures (`old-contradiction`, `sidecar-valid-accepted`, `sidecar-auto-detect-check-input`, the mirror-negative sidecars) to a self-test-only evaluation entry that is not reachable from the CLI check path. Rebind those expectations accordingly.
3. Alternatively, in `evaluateAnchors`, compare every evaluated receipt/pin to `ANCHORS` by bytes regardless of path, and drop the canonical-only gating.
4. Document the scope in SKILL.md and the round-15 lesson: fixture-path evaluation is not authenticated.

### F2 — MEDIUM (C2 classification) — unreferenced worker files are not snapshot-tampering

- `loadWorkerContext` (HEAD ~580–687): an added or unreferenced worker file in `WORKER_DIR` produces `workers:directory_set_mismatch` (669) and therefore a semantic exit 1. `verifySnapshot` covers only `ANCHORS.workers` (one file). Non-`.json` entries are invisible (`readdirSync(...).filter(name => name.endsWith('.json'))`).
- Contrast: a modified existing worker → exit 2 `snapshot_tampered`; a deleted referenced worker → `snapshot_unavailable` exit 2. An injected extra worker → exit 1.
- Correction: enumerate every entry of `WORKER_DIR` in `verifySnapshot`; any entry not in `ANCHORS.workers` (any extension) → `snapshot_tampered` exit 2. Add a `tamper` mirror case for an extra worker file.

### F3 — MEDIUM (C1 A1 truthfulness; false provenance and tautological exit equality) — synthesized exit fields and a false `isolation=cli`

HEAD `scripts/check-user-round-contract.mjs`:
- Line 1252 (`count_committed_<id>`): prints `expected_exit=0 actual_exit=0 … isolation=cli`, but the row is computed in-process from lines 1250–1251 via `runCount(defaultRoot, …)`. No CLI child is spawned. The `isolation=cli` token is false provenance, and `actual_exit=0` is a literal.
- Line 1243 (`reason_negative_control`): `expected_exit=0 actual_exit=0` are literals. `reason=none` and `expected_finding=clean` are literals too. The `result` comes from `negativeMatch`, not from a child process.
- Line 1265 (`count_witness_comparison`): `actual_exit=${witnessMatch ? 0 : 1}`, `top_exit=`, and `exit=` are derived from the same predicate that sets `result=`.
- Line 1273 (`diagnostic_witness_comparison`): `actual_exit=${diagnosticMatch ? 0 : 1}`, derived from the same predicate that sets `result=`.
- `.ufo/waves/round-15/measure.mjs` header (rule 3, "every case is PASS with expected_exit == actual_exit") becomes tautological for these lines. This is the open part of CountMarkerNA F4. The false `isolation=cli` on 1252 is new.

Correction: change 1252 to `isolation=in_process` (or drop the token). Replace the derived `actual_exit` on 1243/1265/1273 with `observed_exit=none`, or spawn the real child and report its status. Have measure count only lines that carry an observed exit.

### F4 — LOW-MED (C1 leak probe scope) — marker probe does not cover the inherited working directory

- Line 1202: `spawnSync(process.execPath, [script, '--repo', root, …], { encoding: 'utf8' })` sets no `cwd`.
- Line 1207: `leaked = existsSync(join(root, test.noMarker))` probes only the fixture root.
- A regression that wrote the marker to the inherited cwd (the lane root) would produce `no_marker=1` (absent) on the fixture root. The current code is safe only because the new evaluator never runs the shell. Its absence check is therefore weaker than the label `no_marker=1 (applicable, absent)` implies.
- Correction: pass `cwd: root` to the child, and also assert absence of `COUNT_WITNESS_MARKER` in `process.cwd()`, or use a unique marker in a fresh temp dir and check that dir.

### F5 — LOW (C2 "every mirror recomputed") — `qualified` is a constant, not derived from proofs

- HEAD line 1008: `expectedMirrorValues` sets `qualification.qualified: true` unconditionally. HEAD line 1475: `buildSidecar` emits top-level `qualified: true` and `status: 'qualified'` as constants.
- Consequence: a sidecar with `qualified: true` and `allProofsComplete: false` passes the qualification mirror check. Refusal then depends on the correction block (`proofs_not_complete`, ~1252–1254) and not on the mirror. The lesson's requirement ("recomputed from authenticated, complete, nonempty proof data") is not met for this field.
- Correction: derive `qualified` = `proofs.length >= 1 && complete && allProofsPass && derived listeningAfter === false`, in both `expectedMirrorValues` and `buildSidecar`.
