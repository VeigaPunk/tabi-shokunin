## Why each survives — clause by clause (v2 line numbers)

- `sessionOf` (`scripts/check-bidi-runtime.mjs:378-392`) checks shape, loopback, and that the url's
  session segment equals the body's `sessionId`. Nothing binds the ws port to the driver that is
  claimed to have served the run, nothing compares the run's base URL to any recorded server, and a
  synthesised pair satisfies all of it. My runs carry ports `43418`/`26636` (G1), `51000`/`51997`
  (G5), `51000` twice (G8) — the gate records them (`out.provenance`) and judges none of them.
- `contextIds` (`:394-408`) collects ids and checks each against `CONTEXT_ID`; there is **no cross-run
  distinctness requirement**, so G8's single context id in both runs passes. A real ChromeDriver
  allocates a fresh context per session: the honest pair is `31B8FE9C…`/`0E62B928…` and the round-32
  RerunDriver pair is `69B4E6A7…`/`584D1980…` (measured from `git show b7d16fb:…`), so every honest
  layout differs while G8 does not.
- Cross-run distinctness is enforced for transcript paths and digests (`:793-794`) and for
  `sessionId`s only (`:807`, `new Set(sids).size !== sids.length`); context ids are shape-checked per
  run (`:803`), never compared across runs. G8 keeps the sessionIds distinct and the context shared.
- `firstShot` / binding (`:816-828`) takes the first *successful* `browsingContext.captureScreenshot`
  in wire order and compares its bytes; it imposes no requirement that the capture precede input
  actions, although the header says the honest capture is "taken after setViewport 640x480, navigate
  … before any input action" (`:83-86`). In both generators the screenshot step sits after
  `input.performActions` (G1 and G5 run1: sends at seq 21 and 25 are `input.performActions`, seq 29 is
  `browsingContext.captureScreenshot`), and the gate admits both — the header's clause is a description
  of the honest capture, not a rule.
- `goldenLines` is exported by the gate in its production bytes (`:874+`, signature with `sessionId`,
  `contextId`, `wsHost`, `wsPort` hooks). A forger does not need to write a generator: importing the
  gate and calling its own fixture emits an admissible transcript except for the screenshot, which one
  real capture supplies.
- Nothing in the receipt leg reads the `host` block, `ranAtUtc`, or `observed` arrays for coherence
  with the transcripts, so a receipt whose `observed` still cites honest fixture values while the
  transcripts are generated is consistent by construction (G5/G8/G9 reuse the honest receipt's
  `observed` unchanged).

## Limits the v2 note should carry (suggested append to §5)

1. **The live leg confers no provenance, only pixel identity.** A receipt with gate-shaped
   `goldenLines()` runs plus one real `captureScreenshot` payload passes offline *and* `--live`
   (G1/G5). Stated in the header as "not proven to have been executed"; the note should say the live
   leg does not narrow it, because the binding's witness bytes are public.
2. **The gate ships the generator that satisfies it.** §5(b)'s "changing the constants is a different
   forgery, not a harder one" is measured as *easier*: G5 imports `goldenLines()` from the gate and
   adds one screenshot (two ids and a port are arguments).
3. **Per-run coherence tells are unenforced.** Identical base, identical ws port and an identical
   browsing-context id across two runs pass (G8); so does a screenshot taken after input actions.
4. **Mixed provenance passes.** One genuine transcript plus one generated transcript is admitted
   offline and live (G9), so the gate cannot even require the receipt's runs to share a capture.
5. **Cost note for any future tightening** (OPTIONAL, and only as a tell-remover): requiring per-run
   browsing-context distinctness and per-run ws-port distinctness would kill G8 and keep H0/H1/H2 green
   (honest contexts and ports differ, measured above), and requiring the first screenshot to precede
   the first input action would kill the positional tell. None of these touches G1/G5/G9 — the class
   stays open, which is why they are a note-level correction, not a claim-level one.
