# na-native-submit — served fixture/provenance attack

Axes: retained-byte identity; dummy-input correlation; action/handler ordering; profile/process boundary; claim scope. Read-only inspection only, except this report. No browser, gate, counter, selftest, build, or formatter execution. No tools installed or updated.

## Findings (observed, high confidence unless qualified)

1. **Attack: substitute an autosubmit fixture or unrelated input.** `corpus/evidence/round-21/runtime/na-native-submit.html:2-3` has a required `q` input and **no `toolautosubmit` attribute**; the input is initially empty, not statically prefilled with a nonce. Lines 5 and 12 embed dummy nonce `de22b3e0-4e2d-4e2b-a4de-00680a4a0630` in the observation object and potential handler response. Producer `scripts/webmcp-lifecycle-round21.mjs:18,105-122,153-160,202` selects `[false, 'submit', 'success']`, generates `randomUUID()`, and supplies the nonce as invocation input. Raw JSON `:132-182` records the identical nonce in sent input (seq9), toolInvoked input (seq11), pre-action page echo, and actual input value (seq12). Pre-action submits/errors are empty and formActive is true. This is correlation of one generated dummy case input, not independent authentication of the experiment.

2. **Attack: mislabel requestSubmit/click or a pre-invocation action as native submit.** Producer `:202-220` requires a nonempty invocation ID before observing and dispatches `document.querySelector('#f').submit()` via `page.evaluate` for this action, not requestSubmit or a button click. Raw `na-native-submit.json:146-250`: invocation result seq10 and toolInvoked seq11 precede pre-action seq12; action marker seq13 is followed by action-complete seq14, navigation seq15, matching Completed response seq16, and post-action observation seq17. Invocation ID is consistently `F38D811156543B28407621D0AA231CA7`. Navigation uses the same frame ID and a new loader ID. Receipt `:193-215` records 252ms initial window with zero matching responses and 503ms after window with output `[{"dummy":"landing"}]`. Producer `:208,224-225` cuts response/navigation summaries at post.seq. **Limit:** dispatch-started is logged after the `page.evaluate` promise is created (`:214,219`), so seq13 is not an instrumented browser-side timestamp proving the exact instant the JS method executed. There is no retained Runtime.evaluate command body in this raw transcript; action mechanism is producer evidence plus an author-recorded action marker.

3. **Attack: claim the observed completion came from the fixture submit handler, or convert lost state to zero submits.** Fixture `:7-15` records submit metadata first, calls preventDefault second, builds the response third, and calls respondWith last (success branch resolves `{ok:true, nonce, q}`). This ordering is explicit source/fixture evidence, **not observed execution of the handler in this case**. Producer `:135-137` serves landing HTML containing JSON-LD `{"dummy":"landing"}`. Raw `:198-250` instead records navigation to `/landing?q=<same nonce>` and Completed with that JSON-LD array. Post-navigation page observations have no old-document nonce/submits/errors; formExists false and input value null. Receipt `:215` correctly retains `submits: null`, not `[]`. Thus no zero-submit assertion, event-flag assertion, or observed preventDefault/respondWith execution is justified for native submit. Knowledge note `corpus/knowledge/webmcp-nonautosubmit-round-21.md:35` states this limit accurately. Inference: the observed result is consistent with the native submission path rather than this handler's promise result; the surviving telemetry cannot independently establish every old-document event that did or did not occur.

4. **Attack: reuse the host profile, or mistake reused PIDs for still-owned processes.** Producer `:128,159,164` creates a fresh mkdtemp root and per-case profile and launches a persistent Chromium context with HOME/TMPDIR under that root; `:171-175` permits only same-origin loopback GET routes. Process ownership uses exact `--user-data-dir=<profile>` argv membership and recursive PPid descendants (`:52-64`). Cleanup refreshes ownership immediately before close, captures PID start ticks, bounds context.close to 5000ms, checks the same PID/start-tick identities, scans once more after close, and conditionally SIGKILLs only matching identities (`:66-104`). Actual raw `:284-387` records nine launch/close PIDs (2454685, 2454692, 2454693, 2454712, 2454732, 2454748, 2454770, 2454779, 2454781) with start ticks, `contextClosed:true`, empty browserPidsAfter/browserPidsSeenAfterClose, and empty blocked/downloads arrays. There is no closeError or forcedCleanup field. **Limit:** actual profile path, full host argv, and raw /proc snapshots are not retained here; isolation/ownership algorithm is source evidence, and cleanup success is recorded observation, not a fresh process inspection or actor-quiescence proof. A process escaping the discovered profile-root/descendant sets is outside this evidence. Producer `:255` removes the temporary tree; this case JSON does not independently attest that removal.

5. **Attack: substitute retained HTML or present producer identity as captured network-body proof.** Read-only sha256sum matched all three recorded hashes:
   - fixture HTML: `8c899a6eff71f0f2433a4003d73182d733a014feebd5425fc9e6ae0eecc2bc6a` (raw `:8-10`);
   - native raw JSON: `1ddf6e89061e7200a5698f7d8b4cf5c5d1f7bfcd8cb0a11ce01b25193ef0bead` (receipt `:247-249`);
   - producer: `5363d576f52e72dc4e82d5838706aa307f371648e73242eed99e9776f06eceb9` (receipt `:4-6`, current `.ufo/waves/round-21/runtime-execution-bounded.json:11-12`).
   Producer `:155-160` writes the same `html` string that it installs in its routes map, and `:140-142` returns that map body. Receipt `:702-710` records GET `/na-native-submit` and GET `/landing?q=<same nonce>`. This supports a producer-to-retained-fixture linkage. **Remaining gap:** there is no independent captured initial HTTP response body/hash, DOM serialization, or browser-side script digest; a matching local fixture hash alone cannot prove every byte actually consumed by the browser. Likewise the retained upstream S100 interpretation is not Arch source-to-binary equivalence (knowledge note `:14-21`). S101 remains own-work runtime evidence.

## Counter/control limits relevant to this attack

- `.ufo/waves/round-21/measure-c1.mjs:74-77` checks HTML hash, nonce occurrence anywhere, and first form tag's autosubmit presence. It does not reconstruct fixture builder output, validate nonce placement in the input/page script, or bind served response bytes. `:81` checks sent q against the nonce, but `:94-96` primarily correlates observations with transcript/summary, not their nonce/input values. Concrete unexecuted attack: remove or alter the HTML nonce echo/handler while retaining the nonce in inert text, updating the nested fixture hash, raw JSON hash, and receipt backlink. Static inspection identifies missing semantic checks; no mutant result is claimed.
- `fixtures/positive-ordered.json:15` represents this fixture as `<form>fixture-nonce-independent-03</form>`, not an executable equivalent of the served fixture; line 3 explicitly says its fixture producer is never executed. That is a counter control, not browser/provenance evidence. `selftest-c1.mjs:31,53` and `fixtures/expected.json:51-54,154` cover ordinary fixture edit and autosubmit-toggle controls (the latter targets the first synthetic case), not the semantic nonce/served-byte attack above. No tests were run.
- Counter cleanup checks `measure-c1.mjs:97-98` do not validate the richer start-tick identity/at-close arrays; they require before PIDs, after empty, contextClosed true, and empty blocked/downloads. Actual native evidence contains richer data, but an accepted counter value would not by itself prove that richer cleanup provenance.
