Not supported by the retained na-click evidence.** `corpus/evidence/round-21/runtime/na-click.html:2-3` contains a required ordinary input and submit button, with **no toolautosubmit attribute**. The nonce is not an initial HTML input value: it is embedded in observation state and response object (`:5,12`); the input is populated through invocation. `na-click.json:132-165` records q=`9acf5007-c443-4473-8764-f04bba30c49d`, invoke result and toolInvoked sharing invocation ID `0B53A87928A9E2638D504C5088EFD942`. Pre-action state already has the same input value, active form, empty submits/errors (`:168-182`); the Completed event echoes both nonce and q (`:192-204`), and the post-action submit record echoes q (`:218-234`). Thus q is read from the actual form by this handler, not merely duplicated from the constant response nonce. Producer `scripts/webmcp-lifecycle-round21.mjs:153-160,202` generates a UUID per case and supplies it as q. This is dummy correlation data, not session material. Generation is source evidence, not an independent randomness audit.

2. **Concrete attack: calling script click()/requestSubmit() while describing a human action. Current wording does not make that claim.** Producer `:212` uses `page.locator('#go').click({timeout:5000})`, not DOM `.click()` or requestSubmit. The recorded isTrusted/agentInvoked true flags (`na-click.json:221-225`) do not establish a human actor.

   Ordering limit: producer creates the click promise **before** recording dispatch-started (`:210-220`), so seq13 is a dispatch-start acknowledgement, not a strict pre-dispatch boundary. This run's response nevertheless appears after seq13 and before click acknowledgement. Post-action summaries are capped at post.seq (`:208,225`), not at cleanup time. No indefinite pending, 12 novel branches, or percentage follows.

Runtime records respondWith as function, one submit, no page errors, active=true during handler and false afterward (`na-click.json:219-234`). The transcript does not instrument each handler statement; preventDefault-before-respondWith is a retained-source fact, supported indirectly by the observed result, not separately timed runtime proof.
