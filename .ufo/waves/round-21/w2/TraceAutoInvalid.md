## Findings by severity

1. **MEDIUM — [INFERENCE] A matching `toolResponded` is not required, so a no-response auto-invalid trace can still be counted.** `measure-c1.mjs:85–87` selects responses by `c.invocationId`, but `event_identity` only rejects a matching response that precedes `toolInvoked`; it never requires `events.length > 0` or an expected `Error` status. `measure-c1.mjs:96` checks receipt response summaries against that same filtered list, and `:100` returns `cases.length` when no findings remain. A concrete counterfactual: retain the command result ID and the matching `toolInvoked`, give seq 12 a different invocation ID, set `preAction.responseCount` to 0 and `after.responses` to `[]`, then update the evidence digest. The response filter is empty, `.some(...)` is false, both summaries agree with the empty filter, and this case can still contribute to the count despite lacking its defining auto-invalid response. No mutant or gate was run. The current capture does **not** exhibit this failure: its only `toolResponded` has the expected ID and `status: "Error"` (`auto-invalid.json:170–180`; receipt `:654–660`).

2. **MEDIUM — [INFERENCE] Invocation-ID-only joining lets a wrong frame or payload be credited as the case invocation.** `measure-c1.mjs:81` requires the sent `frameId` to be a string, not the registered/current frame; `:85–87` finds `toolInvoked` solely by invocation ID and does not compare its `frameId`, `toolName`, or serialized `input` with the sent request. For this case the request payload deliberately has `q: "not-an-email"`, not the case nonce, so the nonce-bearing fixture/page state is not joined through `input.q`. A trace retaining the invocation ID but changing the event-side frame/input (or sending to an unrelated string frame ID) is not rejected by these predicates. In the actual record the correlation is sound: `Page.frameNavigated`, `toolsAdded`, `getFrameTree`, `invokeTool`, and `toolInvoked` all use frame `B1FC6BBBB989233D674FEBA1A38C3849`; the tool is `lifecycle`; sent and event inputs both represent `{"q":"not-an-email"}`; and the result, invoked event, and responded event share `44FE24D2D432D931882EF83CBEC5221D` (`auto-invalid.json:29–51, 63–89, 101–156, 158–180`). This is a missing gate join, not a mismatch in this capture.
