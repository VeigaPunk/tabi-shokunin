## Findings by severity

1. **MEDIUM — Counter can credit a response that precedes `requestSubmit` as the action's result.** This is a counter blind spot, not an observed defect in the retained trace. In `.ufo/waves/round-21/measure-c1.mjs:85-87`, `events` are filtered by invocation ID, and `event_identity` only rejects a response at/before `toolInvoked`; it does not require the matching response to follow the action or its completion. The order check at `:94` orders the invoke command result, pre marker, action, action-complete and post marker, but never orders `events` against the action. `:96` only checks that `after.responses` equals matching events before post. Thus an otherwise consistently resealed record with the matching `toolResponded` inserted after pre-action but before `requestSubmit`, `preAction.responseCount` left at zero, and `after.responses` updated to include it can satisfy those checks and still count this requestSubmit case. The current `selftest-c1.mjs:78-85` / `fixtures/expected.json:164` control covers response-before-invoke, not response-after-invoke-but-before-action; no response-before-action mutant is listed. **No mutant was executed.**

   The retained current trace does *not* exhibit that ordering error: `corpus/evidence/round-21/runtime/na-requestsubmit.json:147-210` has one invoke result and one `toolInvoked` sharing invocation ID `DE3108EE3368EA4B38BE5A3FE48F7178`, followed by action seq13, action-complete seq14, and `toolResponded` seq15. A focused counter control should move the matching response into the pre/action gap, keep the summaries and hashes self-consistent, and require rejection. This finding limits what the count proves about causal attribution; it does not discredit the captured case.
