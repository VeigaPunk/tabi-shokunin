# na-delayed served-fixture/provenance attack

Axes: nonce/receipt identity; actual form configuration; action/handler ordering; profile/process ownership; provenance claim limits. Read-only artifact inspection and SHA-256 arithmetic only. No browser, gate, build, test, formatter, production edit, or delegation. No tools installed/updated.

## Findings (observed unless explicitly qualified)

1. **Attack: substitute a stale/different dummy input or response. Not exhibited by retained records (high confidence).** `corpus/evidence/round-21/runtime/na-delayed.html:5,12` embeds nonce `bb8978d0-4274-45c6-838a-0185a7d0cca3` in the page observation object and response object. HTML input itself is initially empty (`:3`), not prefilled with this nonce. Producer `scripts/webmcp-lifecycle-round21.mjs:155-160,202` generates a UUID for this case, builds/writes/registers the HTML, and supplies that UUID as tool input `q`. Raw `na-delayed.json:132-166` has sent input, returned invocation ID `6B4E7894D6E4EEED79F71A2ACCAD3372`, and toolInvoked event agreeing on identity. Pre-action state `:167-183` shows both page nonce and actual input value equal to it, no submit, form active. Intermediate submit `:198-220` and Completed output `:228-240` echo the same q/nonce. Receipt `receipt.json:464-525` agrees. This is dummy per-case data, not credentials, and UUID generation plus this single retained value is not a repeated-run uniqueness experiment.

2. **Attack: label an autosubmit fixture as non-autosubmit. Not exhibited in retained HTML (high confidence).** `na-delayed.html:2` has toolname/tooldescription and GET action `/landing`, but no `toolautosubmit`; `:3` has ordinary required input, not email. Producer CASES `:23` is `[na-delayed, false, requestSubmit, delayed]`, and conditional attribute generation is `:107`. Raw metadata `na-delayed.json:3-7` agrees. Pre-action seq12 has no submits; first observed submit is after the scripted action. The live DOM's attribute set was not separately serialized, so this establishes retained fixture bytes plus producer intent and correlated observations, not an independent browser DOM-attribute attestation.

3. **Attack: smuggle a human click/auto completion or resolve before the delayed boundary. Not exhibited within recorded window; dispatch-marker qualification remains (high confidence).** Producer `:213` invokes page-script `document.querySelector('#f').requestSubmit()`, not Playwright click or native `.submit()`. Raw seq9-11 invokes/acknowledges the tool, seq12 records pre-action at 1792588030363, seq13 action-dispatch marker, seq14 action-complete at 1792588030364, seq15 delayed-before-release at 1792588030615, seq16 release marker, seq17 Completed, seq18 final observation at 1792588031117 (`na-delayed.json:132-266`). There is no toolResponded before seq16 in the retained frames. Intermediate state is active with one submit and no errors; final state is inactive with one submit, no errors, same URL. Receipt `:471-502` reports 254 ms initial window without response, 754 ms after-action window, one correlated Completed, no navigation. Intermediate hold after action-complete is 251 ms by recorded timestamps, not a general pending/eventual-settlement guarantee. `isTrusted:true`/`agentInvoked:true` are logged flags, not proof of a human cause. **Limit:** producer creates the `page.evaluate` promise at `:213` before logging dispatch-started at `:219`; seq13 is not an exact before-execution fence. Release marker likewise precedes awaiting `window.release()` (`:222`), so seq16 records the release request boundary, not a separately acknowledged settlement instant. The action-complete fence and intermediate observation still exist before release.

4. **Attack: reverse preventDefault/respondWith ordering or silently substitute immediate fulfillment. Not exhibited in retained handler (high confidence).** `na-delayed.html:7-15` first logs submit flags/q, then `e.preventDefault()` (`:9`), sets mode delayed (`:10`), captures `{ok:true,nonce,q}` (`:12`), and synchronously passes a newly constructed unresolved Promise to `e.respondWith` (`:14`). Promise executor installs `window.release=()=>resolve(value)`; it does not resolve there. Producer `:222` explicitly evaluates release only after the intermediate observation. The retained raw response arrives after the release marker. This directly inspects JS fixture behavior; it does not prove Chromium's internal implementation ordering or binary/source equivalence.

5. **Attack: reuse a host profile or overstate cleanup from context.close alone. Finite owned-process evidence supports isolation/cleanup; universal quiescence remains unproved (high confidence for recorded fields).** Producer creates a unique temporary root (`:128`), uses case-specific profile `join(temp,id)` (`:159`), and passes that profile to launchPersistentContext with HOME/TMPDIR set to the temp root (`:164`). Loopback server is bound at `:144`; request routing permits only matching origin GET (`:171-175`), downloads are disabled/recorded (`:164,177`). `na-delayed.json:334-436` records nine launch/close PIDs, start ticks (root PID 2463440, ticks 8701330), contextClosed true, blocked/downloads empty, no profile-associated PIDs seen after close, empty identity-matched survivor list. No forcedCleanup field is present. `closeOwnedContext` refreshes profile process ownership before close, retains PID/start-tick pairs, bounds close to 5 s, checks identities after close, and conditionally kills matching survivors (`:72-103`). This is more than contextClosed alone. **Limit:** profile pathname/effective process argv are not retained in the case; ownership is inferred from the inspected producer. processTree discovers profile-argument roots and currently parent-linked descendants (`:52-64`), so detached/reparented descendants missed by its snapshots are outside the guarantee. Empty recorded survivors is not global actor quiescence. Cleanup deadlines are not exhaustive OS/signal fault-injection evidence.
