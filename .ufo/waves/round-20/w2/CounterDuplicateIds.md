## 1. Producer logic at 4ae9981

- `checkDecisions` 388-404: counts each pinned entry by id (389-393). For each pinned id, count 0 adds `decision_missing` (401) and count > 1 adds `decision_duplicate_id` (402). Missing and duplicate never fire for the same id; they can co-fire across ids.
- `checkDecision` 322-371: non-object entries (323-326) emit `decision_shape` and return null. Non-string or unknown ids (329-335) emit `decision_shape` or `decision_unknown_id` and leave `pinned` null. Either way the entry is not counted, so every uncounted entry has a finding. Key-set violations (327) emit `decision_shape` but the entry still counts when its id is pinned.
- Metric: `decisionCount` 210-212 = raw `decisions.length`. `summarize` 279-282 sets exit 0 only with an empty finding set.
- Invariant, by inspection (`evaluate` 560-570, `evaluateComplete` 530-554): exit 0 holds only when both files are absent (count 0, verdict `baseline`) or when count = 12 and every pinned id appears exactly once (`clean`). Duplicates and invalid entries cannot pad a clean count.
- The CLI emits the raw count under exit 1 (line 756, verdict `failed`). The contract admits only exit 0, so a consumer that ignores verdict or exit could read 12 from a padded state. Residual risk only.
- Findings are reason strings only. They do not name the LC id.

## 4. Producer gap: unclassified rows are invisible to the table check

- `LC_ROW = /^\|\s*LC\d{2}\s*\|/` (line 99). `checkTable` skips every line that fails it before the in-section and outside-section checks (line 431).
- Consequence: a section row such as `| LC05 (repeat) | ... | S096:218-221 |` is ignored. With a valid 12-entry manifest and the 12 canonical rows, the producer returns count 12, exit 0, verdict `clean`. The stated rule is that table rows "must equal the renderable manifest decisions as a multiset." That rule is violated and not detected.
- Asymmetry: an id typo in the manifest (`LC13`, `lc12`) is caught by `decision_unknown_id` (329-335). The same typo in the note is silent for lowercase and caught as extra for `LC13`, which passes LC_ROW.
- Recommended minimal fix (producer, for main to decide): classify section rows by `/^\|\s*LC/` at line 431 (and the outside-section test), keeping the canonical `LC\d{2}` match for expected rows. The header `| ID | ... |` and separator rows do not start with `LC`, so they stay excluded. valid_all12 and the real note are unaffected (the real header reads `Source anchor`, which this rule ignores). Under this fix R12 gives 12 / 1 / `[table_row_extra]`.
- Alternative: if the LC_ROW-only rule is intentional, document it and pin R12 as 12 / 0 / `[]`. Do not leave it implicit.
