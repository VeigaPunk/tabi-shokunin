## HIGH

H1. toMatchAriaSnapshot cannot run from a plain .mjs script.
Evidence: playwright/lib/matchers/expect.js:13037-13044 — `const testInfo = expectConfig().testInfo; if (!testInfo) throw new Error("toMatchAriaSnapshot() must be called during the test")`.
Consequence: scripts/aria-loopback-round13.mjs using only the `playwright` library can call locator.ariaSnapshot() and get YAML, but cannot invoke the Playwright matcher. Two honest options:
  (a) run as a Playwright Test spec through the `playwright/test` entry (types/test.d.ts exists in the 1.64.0 package). Then the claim may say "Playwright 1.64.0 toMatchAriaSnapshot matched template T under children mode M". The runner then is a spec file, not a bare script — the spec path must be stated in the artifact.
  (b) keep the bare .mjs and compare the YAML string itself. Then the claim may only say "runner-side exact string comparison of the ariaSnapshot YAML to template T". Playwright's contain/equal/deep-equal and partial-matching semantics are NOT exercised, so the docs' matcher claims (§4) stay docs-held.
Recommendation: if the C2 point is the matcher semantics, use (a). Do not write (b) and label it toMatchAriaSnapshot.

H2. Playwright Test writes outside the write set by default.
Under (a), the default reporter and output dir write test-results/ and playwright-report/ into the cwd. Those paths are outside "scripts/aria-loopback-round13.mjs plus corpus/evidence/round-13/aria". Set outputDir to an isolated temp dir and reporter to a non-file reporter, or run from an isolated temp project directory. Verify afterward that the repo tree gained no files outside the write set.

H3. Vacuous-pass hazard in the matcher.
expect.js:13044 (and the same guard at :12537, :12592): `if (expectConfig().ignoreSnapshots) return { pass: !this.isNot }`. types test.d.ts:421 `ignoreSnapshots?: boolean`. If the config sets ignoreSnapshots, toMatchAriaSnapshot passes without comparing. The runner must assert ignoreSnapshots is absent/false and record the effective expect config in the artifact. Also keep updateSnapshots at 'none' for the demonstration: 'all' (expect.js:13064 area) replaces the expected value with an impossible match, and 'missing'/'default' generate baselines when the expected string is empty. A wrong config must make the run fail, not pass.

H4. Runtime pin mismatch between "existing browser" and the Playwright pin.
The spec says "pinned runtime … use existing browser with isolated temp profile". The package pin is 1.64.0 → Chrome for Testing 156.0.8078.4 (cache chromium-1248). The host /usr/bin/chromium is 152.0.7977.82. Using /usr/bin/chromium through executablePath would make a second unpaired runtime; it must not be presented as the 1.64.0 runtime. Recommendation: the claim names "Playwright 1.64.0 + Chrome for Testing 156.0.8078.4 (rev 1248, cache path recorded)". The runner should assert browser.version() === 156.0.8078.4 and record the executable sha256, and fail on mismatch. No browser download is needed; the build is already installed.

H5. Module resolution. A bare `import … from 'playwright'` from scripts/*.mjs does not resolve: the repo has no package.json, and ESM ignores NODE_PATH. Options: (i) absolute import of the fnm global path (version-specific, fragile); (ii) install exact `playwright@1.64.0` into an isolated temp dir and record the integrity hash. Any package.json or node_modules in the repo is outside the write set. Any install performed must be recorded as tool/version/channel/reason per the operator directive. This review performed no install.

## MEDIUM

M1. Egress. Playwright's launch switches (coreBundle.js, `--disable-background-networking` present) reduce browser background traffic but do not establish no-egress. cdp-evidence-patterns.md §1 E4 already recorded Google traffic from a fresh profile. Claim only: "every page request recorded in this run targeted 127.0.0.1 (page.on('request') shape recorded)". Do not claim browser-level no-egress. The fixture must contain no external font, script, or image URLs.

M2. Profile boundary. Playwright's launch uses a temporary --user-data-dir and a remote-debugging pipe (`--remote-debugging-pipe` string present in coreBundle.js; count 3, not separately verified at runtime). This satisfies the profile-isolation note only if the runner never passes channel 'chrome', never names the default profile, and never sets a TCP debugging port on the default profile. State this in the artifact.

M3. Strictness. The runner should record `getByRole(role,{name}).count()` === 1 immediately before ariaSnapshot and fail otherwise. Never use .first() to clear a violation (knowledge doc §3, S023 §Strictness).

M4. Negative controls are required. Partial matching drops omitted names and attributes (S024 §Partial matching; doc §4). A passing template proves little without discriminating cases. Minimum set:
  - a mutated accessible name that must FAIL;
  - a `/children: equal` template with one extra child that must FAIL;
  - the absence case under default mode (no baseline → fail, not pass).
Without these, "matched" has no discriminating power and the claim is weaker than the doc's own rules.

M5. Retry policy. Set retries explicitly to 0. Any pass-on-retry must be classed flaky, and every attempt kept (S013, corpus/knowledge/web-flake-retry-evidence.md). The matcher's timeout is a window, not continuous match (doc §6 record shape).

M6. Determinism. Two independent cold-profile runs with byte-identical YAML sha256 is the minimum determinism statement. It is environment-scoped (this host, this build, this fixture). Do not generalize to other builds or pages.

M7. Ladder placement. Per SKILL.md:402 and knowledge doc §5–§6, an ARIA YAML is a state-claim structural witness from a single producer (Playwright). It is not an independent second signal against DOM shape (doc §6 "ARIA is not an independent second signal"). A static template run sits at rung-1 style evidence (sha-pinned bytes plus idempotence re-run), not rung 3. Counting YAML + DOM snapshot as two signals is rejected.
