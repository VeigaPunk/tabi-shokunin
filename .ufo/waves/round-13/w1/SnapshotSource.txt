4. CORE MECHANICS: ACTUAL `ariaSnapshot` API
================================================================

A. Method Declarations & Signatures:
- `locator.ariaSnapshot(options?: AriaSnapshotOptions): Promise<string>`
  * Added in: v1.49
  * Scope: Constrained strictly to the element subtree matching the locator query.
  * Options:
    - `depth?: number` (Added v1.59): Limits tree traversal depth.
    - `mode?: "default" | "ai"` (Added v1.59): "ai" emits `[ref=eN]` IDs and traverses `<iframe>` elements without waiting.
    - `boxes?: boolean` (Added v1.60): Appends `[box=x,y,width,height]` in CSS pixels relative to viewport.
    - `signal?: AbortSignal` (Added v1.62): Cancels the snapshot operation.
    - `timeout?: number`: Maximum wait time in milliseconds.
  * Return: Serialized YAML string representing the accessibility subtree.

- `page.ariaSnapshot(options?: AriaSnapshotOptions): Promise<string>`
  * Added in: v1.59
  * Scope: Full page body accessibility tree (`page.locator('body').ariaSnapshot()`).
  * Options: Identical options (`depth`, `mode`, `boxes`, `signal`, `timeout`).
  * Return: Serialized YAML string for the entire document body.

- `locator.ariaSnapshotJSON(options?)` & `page.ariaSnapshotJSON(options?)`
  * Added in: v1.63
  * Return: Structured JSON AST instead of YAML markup (properties: `role`, `name`, `text`, `children`, `checked`, `disabled`, `expanded`, `level`, `pressed`, `selected`, `url`, `placeholder`, `ref`, `box`, `cursor`).

B. API Spelling & Existence Note (Resolution of Routed Inquiry):
- `page.ariaSnapshot()` is the canonical, supported method on `Page` (introduced in v1.59).
- `locator.ariaSnapshot()` is the canonical, supported method on `Locator` (introduced in v1.49).
- There is NO spelling error or deprecated alias. In earlier versions (v1.49–v1.58), `page.ariaSnapshot()` did not exist directly on the `Page` object; page-level snapshots had to be taken via `page.locator(':root').ariaSnapshot()` or `page.locator('body').ariaSnapshot()`. From v1.59 onwards, `page.ariaSnapshot()` is directly supported and equivalent to targeting the main frame document body.

5. CORE MECHANICS: CHILDREN `contain` / `equal` / `deep-equal` SEMANTICS
================================================================

A. Location & Attribution:
- Documented in S024 under heading `§Strict matching` (h3 id="strict-matching").
- The verifier note in round 12 is confirmed: §Snapshot matching covers basic structural matching (single vs multi-root, case/whitespace normalization, order sensitivity); §Strict matching defines the `/children` property and the three matching modes.

B. The Three Modes & Exact Matching Logic (Verified from `playwright-core` AST):
1. `contain` (Default Mode):
   - Template directive: `- /children: contain` (or omitted).
   - Core implementation: `containsList(node.children, template.children)`.
   - Behavior:
     * Requires all listed template children to appear in relative sequential order.
     * Unlisted sibling children in the DOM/ARIA tree are accepted and skipped.
     * An empty template children list matches any number of children (fully unconstrained).
2. `equal`:
   - Template directive: `- /children: equal`.
   - Core implementation: `listEqual(node.children, template.children, false)`.
   - Behavior:
     * Direct children of the node must match the template 1-to-1 in count, identity, and sequence.
     * If `template.length !== children.length`, the assertion fails immediately.
     * Extra unlisted direct children cause immediate failure.
     * Non-recursive: nested descendants of direct children revert to default `contain` matching unless they also declare strictness.
3. `deep-equal`:
   - Template directive: `- /children: deep-equal`.
   - Core implementation: `listEqual(node.children, template.children, true)`.
   - Behavior:
     * Exact 1-to-1 equality is enforced recursively down every branch of the subtree.
     * Any unlisted child at any nesting depth causes immediate match failure.
     * Override capability: A nested child node can declare `/children: contain` to locally relax strictness and allow arbitrary extra children within that specific sub-branch.

C. Global Configuration:
- Configurable in `playwright.config.ts`:
  ```ts
  expect: {
    toMatchAriaSnapshot: {
      children: 'equal', // sets default mode across all toMatchAriaSnapshot calls
    },
  }
  ```
- Individual snapshot templates override global configuration by specifying an explicit `/children` key.

6. CORE MECHANICS: CHECKED-STATE SEMANTICS
================================================================

A. Roles with Checked Support (`kAriaCheckedRoles` in `playwright-core`):
- `checkbox`, `menuitemcheckbox`, `option`, `radio`, `switch`, `menuitemradio`, `treeitem`.

B. Extraction from DOM (`getChecked`):
- Native HTML controls (`<input type="checkbox">`, `<input type="radio">`):
  * `element.indeterminate === true` evaluates to state `"mixed"`.
  * `element.checked === true` evaluates to boolean `true`.
  * `element.checked === false` evaluates to boolean `false`.
- ARIA semantics (`aria-checked` attribute):
  * `aria-checked="true"` evaluates to boolean `true`.
  * `aria-checked="mixed"` evaluates to state `"mixed"`.
  * `aria-checked="false"` (or missing/invalid) evaluates to boolean `false`.

C. Serialization in YAML (`ariaSnapshot()` generator):
- When checked (`true`): Emits `[checked]`.
- When indeterminate (`"mixed"`): Emits `[checked=mixed]`.
- When unchecked (`false`): The checked attribute is completely omitted from YAML output (renders as bare `- checkbox "Label"`).
- Note: The generator NEVER outputs `[checked=false]`.

D. Template Matching (`toMatchAriaSnapshot()` matcher):
- Explicit `[checked]` or `[checked=true]`:
  * Parses as `template.checked = true`.
  * Requires `node.checked === true`.
  * If the element is unchecked (`node.checked === false`), the assertion FAILS.
- Explicit `[checked=false]`:
  * Parses as `template.checked = false`.
  * Requires `node.checked === false`.
  * If the element is checked (`node.checked === true`), the assertion FAILS.
- Explicit `[checked=mixed]`:
  * Parses as `template.checked = "mixed"`.
  * Requires `node.checked === "mixed"`.
- Omitted checked attribute in template (e.g. `- checkbox "Agree"`):
  * `template.checked` is `undefined`.
  * In `matchesNode()`: `if (template.checked !== void 0 && template.checked !== node.checked) return false;` is bypassed.
  * Partial matching rules apply: the assertion PASSES regardless of whether the checkbox is checked, unchecked, or indeterminate.

8. CRITICAL BOUNDARIES & OVERCLAIM DEFENSES
================================================================

1. ARIA Snapshot != Visual Screenshot:
   - ARIA snapshots capture the computed accessibility tree derived from ARIA attributes and HTML semantics.
   - ARIA snapshots carry zero data about rendered pixels, CSS colors, background images, font metrics, visual layout shifts, or clipping.
   - The `boxes: true` option (v1.60+) adds viewport bounding boxes in CSS pixels, but does NOT represent rendered visual appearance.
2. ARIA Snapshot != Accessibility Audit:
   - Matching an ARIA snapshot does NOT prove WCAG conformance.
   - Snapshots do not verify color contrast, keyboard tab order, focus traps, or screen-reader announcements.
3. ARIA Snapshot != Independent Signal from DOM:
   - ARIA snapshots and DOM structures are derived from the same source document. Agreement between them does not constitute independent corroborating signals on the evidence ladder.
4. AI Ref != Webbridge Ref:
   - Playwright's `[ref=eN]` (v1.59+ `mode: 'ai'`) is a transient internal reference for AI workflows and is distinct from webbridge `@e` accessibility refs.
