## Behavior / correction
The old §2 "Byte truth" row (:71) said a "response" data collector "must exist when the
response body is collected", which is a true but under-specified necessary condition. The
appendix states the operational timing: the collected-data record and its `cloned body`
are created by the "WebDriver BiDi clone network response body" step only when the
session's collector map is non-empty, i.e. a collector must already be registered when
the response is created/cloned. `network.getData` (§7.5.5.8) retrieves an existing
record; null record -> `no such network data`, null bytes -> `unavailable network data`,
pending -> await "network data collected". It never starts collection. Bytes storage also
requires a collector whose `dataTypes` contains `"response"`, context match, and size
within `max encoded item size`; total storage is capped by implementation-defined
`max total collected size`.
