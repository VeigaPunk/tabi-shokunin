4. EXACT API VERSION SCOPE & CHRONOLOGY
================================================================

- v1.14 (September 2021) — Foundation of Locators & Strictness:
  - Playwright introduces the `Locator` abstraction as distinct from `ElementHandle`. Locators capture retrieval logic lazily rather than pointing to a static node reference.
  - Locators are made "strict by default" for single-element actions.
  - Page-level action methods gain `strict: true` opt-in parameter.
  - Web-first auto-retrying assertions (`expect(locator)...`) are introduced.

- v1.17 (January 2022) — Frame Traversal:
  - Introduction of `FrameLocator` (`page.frameLocator()`, `locator.frameLocator()`) enabling seamless lazy locators through iframe boundaries.

- v1.18 – v1.19 (February–March 2022) — Subtree & Text Filtering:
  - Introduction of `hasText` and `has` filtering options (`filter({ has: locator })`).

- v1.21 – v1.22 (April–May 2022) — Role Selector Engine:
  - Internal ARIA role selector engine introduced (`role=button[name="..."]`).
  - `locator.filter()` method introduced for narrowing locator scopes.

- v1.27 (October 2022) — Dedicated Semantic Locator API:
  - Official launch of user-facing semantic locator methods across `Page`, `Locator`, `FrameLocator`, and `Frame`:
    - `page.getByRole(role, options)`: Locate by ARIA role, ARIA attributes, and accessible name.
    - `page.getByLabel(text, options)`: Locate form input by label text, aria-labelledby, or aria-label.
    - `page.getByPlaceholder(text, options)`: Locate input by placeholder text.
    - `page.getByText(text, options)`: Locate by rendered text content.
    - `page.getByAltText(text, options)`: Locate image/area by alt text.
    - `page.getByTitle(text, options)`: Locate element by HTML title attribute.
    - `page.getByTestId(testId)`: Locate by configured test id attribute.

- v1.34 (June 2023) — Locator Combinators:
  - Added `locator.and()` and `locator.or()` operators for simultaneous condition matching and fallbacks.

- v1.49 – v1.59 (November 2024 – January 2025) — ARIA Snapshots:
  - `locator.ariaSnapshot()` introduced in v1.49.
  - `page.ariaSnapshot()` introduced in v1.59.

- v1.60 (March 2025) — Accessible Description Matching:
  - `description` option added to `getByRole()` matching W3C AccName accessible descriptions.

- v1.63 (Early 2026) — JSON Snapshots & Visibility Filter:
  - `locator.visible()` method introduced.
  - `page.ariaSnapshotJSON()` and `locator.ariaSnapshotJSON()` added.

- v1.64 (Current Stable Documentation Baseline & Host Global Runtime):
  - `locator.within()` introduced for scoped subtree matching.
  - WebMCP experimental integration (`page.webmcp`).
  - Matches the globally installed `playwright@1.64.0` verified on host in RuntimeInventory.

5. BOUNDARIES, INFERENCES, AND OVERCLAIM WARNINGS
================================================================

- Not an Accessibility Audit:
  Playwright docs state explicitly: "role locators do not replace accessibility audits and conformance tests, but rather give early feedback about the ARIA guidelines." Using role locators verifies that a control is perceived with that role and name, but does not prove WCAG conformance, contrast compliance, or keyboard focusability.

- Re-Resolution Mechanics:
  Locators evaluate at action execution time. Unlike Selenium or Puppeteer `ElementHandle`s which can go stale (`StaleElementReferenceException`), Playwright locators automatically re-query the DOM on each action invocation (`click`, `fill`, etc.). If a framework re-renders the element between two actions, the locator transparently picks up the fresh element.

- Opt-Out Strictness Hazards:
  Using `locator.first()`, `locator.last()`, or `locator.nth()` suppresses Playwright's strictness defense. The docs explicitly warn that these methods are "not recommended" because layout or order shifts will silently interact with an unintended element. Similarly, `or()` is not a disambiguator: if both alternative conditions match simultaneously, strict mode will throw.
