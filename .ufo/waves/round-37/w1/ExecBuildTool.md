### 5a. It really is inert on this round's pin set

Running the **frozen round-36 bytes** (`git show 99437d2:.ufo/waves/round-36/baseline/c1-drift-audit-build.mjs`, sha256 `c8153a5a6d9e29a3991a0d753c482d2963aaa0e224978386d96ad661c62a2be1` = round-36 `claims.json` digest) against the same repo/fleet/out:

Mechanism, read from the source: in the builder `PINS` is used at exactly one place — the drift-set membership test `h !== PINS[s]` (line 66 of the round-36 bytes) — while the per-row *pin* is parsed out of the screen ref itself (`m[2]`) and the *head* comes from the digest-bound delta pins JSON. Membership recomputed under all three PINS blocks:

```
drifted(round-36 pins) = drifted(v2 pins) = drifted(counter v5 pins)
  = {chousa, kaidoku, kake, kama, kasegi, kengaku, kumitate, mado, mori, revenger, tameshi, tsukuroi}
```

`kama` is drifted under both because `deltaPins.kama = 3a600d2f729828419aaea34cc402c8b0d20fb720` differs from **either** pin value. A 39-char literal can never equal a 40-hex delta head, so the typo can only ever make a lane *spuriously* drifted, never silently drop one — hence "inert" on this pin set.

## 6. Adjacent findings (advisory for the L1; neither violates a frozen C1 target)

### F1 — the v2 guard does not enforce 40-hex, so a *resolvable* truncated pin still passes silently (operability)

The C1 counter v5 enforces `if (!/^[0-9a-f]{40}$/.test(rev)) throw new Refusal('revision must be 40-hex')` (`c1-adjacency-sweep-v5.mjs:142`) before its `rev-parse`. The v2 **builder** has no such check — its guard is resolvability-only (`git rev-parse --verify --quiet <pin>^{commit}`), and git happily resolves a 39-char *unique abbreviation* of a real commit.

Demonstrated on scratch copies of the frozen bytes:

* kagi pin truncated to 39 chars (drop the last hex) → **guard passes, EXIT 0**, but the drift set silently changes (13 drifted lanes instead of 12 — `kagi` spuriously added) and the ledger grows **307 → 363 rows**: 56 spurious `kagi-shokunin@…` rows appear — `evidence/F1-ledger-truncated-kagi-pin-363rows.tsv` (364 lines = 363 rows + header).
* audio pin truncated to 39 chars → EXIT 0 and the ledger looks *unchanged* (307 rows — `evidence/F1-ledger-truncated-audio-pin-unchanged-rows.tsv`) — but only because audio has zero screen rows; the **drift set is silently wrong** (13 lanes, `audio` spuriously drifted, while the counter says it is not), so the divergence surfaces the moment an audio row exists.

The *specific* historical defect (the middle-of-hash dropped `d`) **is** caught by the guard (case A above), so the routed defect 2 is closed as recorded; what remains open is the general truncation class. Suggested round-38 fix (lane-owned, next freeze): give the builder the same `40-hex` precondition the counter has, before `rev-parse`, e.g. reject any `PINS` value that is not `/^[0-9a-f]{40}$/`; optionally additionally require `PINS[sib]` to equal the pin the screen refs cite.

### F2 — the builder reads through `refs/replace`; the counters do not (operability / provenance)

`c1-adjacency-sweep-v5.mjs:137` and `c2-firefox-bidi-v3.mjs:121` both spawn git with `GIT_NO_REPLACE_OBJECTS: '1'`. The v2 **builder's** git env (`c1-drift-audit-build-v2.mjs:42`) does **not** — it inherits replace refs from the sibling repos it reads.

Demonstrated: a scratch fleet whose `kama-shokunin` clone carries `refs/replace/e8fa87ef…bd688d` → a commit with a *different tree* (the cited `consumer-registry.md` lines removed). The builder, run against that fleet:

* **EXIT 0**, stdout `drift-audit: 307 rows (299 unchanged, 8 moved, 0 stale)`;
* it emits **5 forged kama `moved` rows** with relocation numbers computed from the *grafted* tree (`consumer-registry.md:61 → :62`, `:236 → :238`, `:277 → :280`, `:325 → :329`, `:332 → :337`) where the honest ledger says `unchanged` — `evidence/ledger-replace-graft-forged.tsv`.

Good news: the forgery does **not** reach a true predicate. The frozen C1 counter (which sets `GIT_NO_REPLACE_OBJECTS=1`) run against the same fleet with the forged ledger committed → **EXIT 1, `predicate: false`**, `drift.total 307`, `drift.auditCoverage 302`, **5 × `audit-status-mismatch`** (`moved != observed unchanged`) — `evidence/c1-v5-replace-graft-fleet.json`.

So the C1 *measurement* is safe, but the **builder's own receipt is graft-readable**: the byte-for-byte regeneration comparison an operator performs can be produced against a grafted sibling repo with no error and no warning. Suggested round-38 fix (lane-owned, next freeze): add `GIT_NO_REPLACE_OBJECTS: '1'` to the builder's git env and/or refuse to run when a sibling repo carries `refs/replace/*`.
