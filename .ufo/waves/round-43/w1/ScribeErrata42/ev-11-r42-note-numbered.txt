10:# Committed-bytes verification (round 42)
11:
12:## Claim
13:
14:Round-41 verifier defect D1 was a landing-class calibration failure: the round-41
15:report, SCORECARD and lesson called `corpus/evidence/round41/playwright-egress/`
16:receipt files a "durable receipt" while `git ls-tree` at the pushed tip listed zero
17:files under that path — the bytes existed only as untracked working-tree files. A
18:claim's evidence exists when a revision addresses it, not when a path exists on a
19:checkout. `git ls-tree` "Lists the contents of a given tree object, like what
20:"/bin/ls -a" does" (S149, NAME/DESCRIPTION) — the instrument that would have caught
21:D1 before filing, and the instrument the round-42 checker's R1/R4 checks are built on.
22:
23:## Decision table — where evidence is read from
24:
25:| Surface | Reads | Catches | Misses |
26:|---|---|---|---|
27:| working-tree path (`test -f`, `wc -c`) | the checkout | nothing about history | untracked files (D1's exact failure), index-vs-HEAD skew, jj working-copy sweeps |
28:| `git ls-tree -r --name-only <rev> -- <path>` | the committed tree | absence from the revision under claim | blob validity (pair with `cat-file`) |
29:| `git show <rev>:<path>` + sha256 | committed bytes | byte drift between claimed and delivered revisions | nothing about reachability (pair with `ls-remote` for the branch tip) |
30:| `git ls-remote origin refs/heads/<branch>` | the pushed tip | "committed but never pushed" (the §4 pre-report gate) | local-only revisions |
31:
32:## Rules distilled (each falsifiable by the cited incident)
33:
34:1. Every report/SCORECARD/lesson evidence pointer names a path **and** the revision
35:   that must contain it; the verifier's first command is `git ls-tree` at that
36:   revision (D1: cited-as-durable, absent at `ef41e539`).
37:2. A baseline count stored as a control file carries its counting command next to
38:   the digit; an empty control file is a missing control, not a zero (D3:
39:   `c1-baseline-noop.out` committed 0 bytes in round 41).
40:3. Sources rows carry quotes as verbatim substrings of a committed staged copy of
41:   the source, so quote fidelity is checkable from bytes alone (D2: spliced S146
42:   quote; corrected by S148).
43:4. Large evidence files must be committed as explicitly named files: the lane
44:   helper skips new files over 1 MiB inside a named directory, so D1's two
45:   ~1.1 MB files silently stayed untracked when the directory was committed.
46:
47:## Falsification
48:
49:The round-42 checker (`.ufo/waves/round-42/counters/check-routed-defects-round42.mjs`)
50:returns exit 1 with `r1a-receipt-absent`/`r1b-witness-absent` at baseline
51:`34e177959d1b7ce04afb85a001420e02631ce79e` (committed red control
52:`.ufo/waves/round-42/controls/c2-baseline-red.json`) and exit 0 once the receipt
53:bytes and their sha256 binding to the committed measure record are present at the
54:measured revision. Mutation seats attack the checker's refusal surfaces in the
55:round-42 wave.
56:
57:## Limitations
58:
59:- `git ls-tree` sees the named revision only; a claim about "the repo" must pin the
60:  revision (branch tip moves).
61:- Byte presence is not provenance: sha256 binding to an independently recorded
62:  measure document (as R1 does) is the weakest binding used here; producer digests
63:  (round-41 chain) remain the stronger instrument for executable evidence.
