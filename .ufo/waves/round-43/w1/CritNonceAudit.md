# CritNonceAudit — nonce freshness and exposure

## Result

No in-model nonce freshness break found. The environment echo exposes the nonce to the pinned driver by design; the nonce is a binding token, not a secret. It is generated by the wrapper, then expected to be echoed through the receipt, witness, and signed measure record. The counter checks that consistency and authenticates the signed record, but does not maintain a nonce history or independently establish nonce age/uniqueness.

## Counterexample considered

The strongest nonce-specific counterexample is replaying a genuine prior receipt/witness/measure pair: the counter has no seen-nonce set or created-at freshness check, so nonce validation by itself is consistency-only. This does not demonstrate a do-nothing reach. A direct counter invocation additionally needs a signature over its newly generated challenge; the wrapper keeps its per-invocation private key in memory and signs the challenge only in the wrapper-to-counter exchange. More importantly, the frozen residual model explicitly treats harvesting a per-invocation private half as requiring a prior honest chain run and says rescoring that genuine prior pair proves only that same run, binding no new claim content. I found no route in the declared model to turn nonce exposure or that replay into exit 0 without a browser run.
