# CritCorrectionGaming — correction text is not remeasurement

## Axes and verdict

Axes attacked: **calibration** (does correction evidence establish the claimed oracle value?), **operability** (can the rule be implemented and tested deterministically?), and secondarily **freshness/provenance** (what revision and run does the correction describe?). Verdict: the source rule has a genuine defect: it does not require the correction paragraph itself to show an independent remeasurement or its provenance. The gate's oracle comparison is a useful safeguard against a *wrong number*, but not against stale or fabricated prose that happens to repeat the current number. A correction is testimony, not evidence of a run. One paragraph serving two findings is not intrinsically wrong, but under the current paragraph-wide matching it can create false associations; require per-finding binding rather than globally banning multi-finding paragraphs.

## Evidence and strongest objections

`claims.json` round 27 C1 declares an append-only correction that names the same script, states the oracle-correct number, has a correction marker, and cites the superseded line (`.ufo/waves/round-27/claims.json:24`). Its control says only that a wrong oracle number or missing citation must not supersede (`:30`). Neither clause requires a new measurement, a command/run receipt, or revision binding. The shipped implementation at `scripts/check-selfassessment.mjs:309-327` confirms this: it looks for a later paragraph containing the same script, `/supersed|correct/i`, any `:\d+/`, and `statedTallyNumbers(text).includes(f.observed)`. No run receipt or measurement provenance is checked.

**Strongest honest objection (fixable rule defect):** the claimed measurement can be honestly reported yet stale. Suppose a gate measured 12 at correction time; the paragraph records 12 and cites the right finding line. Later the gate changes to 13, but the historical paragraph remains. The counter now reads the current oracle (13), so 12 does not clear it; this is safely fail-closed, but the historic correction cannot disposition the old stale mention even though it was valid when written. Conversely, if the number coincidentally remains 12 but the measurement context/revision changed, the paragraph passes without establishing that anyone reran anything. The gate does independently measure the *current* oracle via `gateTally(repo, rev, script, cache)` (`:299-305`), so a false numeric assertion ordinarily cannot clear a finding unless it equals that measured value; this is meaningful protection, not no protection. But equality of prose with the oracle does not prove the assertion was freshly measured or tied to the same revision. This is a provenance/contract gap, not a claim that every accepted correction is false.

**Strongest gaming objection:** append a correction paragraph naming the script and exact stale line, containing a correction marker and the number the current gate happens to report, without running the gate. It clears by text equality alone. More generally, the current matching is paragraph-wide: another bullet's script, marker, citation, and tally can combine into one passing paragraph, so even the exact number and citation need not be in one correction entry. This is amplified by the already-demonstrated false-citation behavior: the prior wave-1 review measured fixtures where a nonexistent/wrong `:N` sufficed and a later round-1 paragraph cleared `LOG.md:221` without citing it (`.ufo/waves/round-27/w1/CritC1Supersession.md:21-35, 71-95, 101-115`). That is a separate, stronger predicate defect; do not mistake this assignment's remeasurement concern for the already-established line-binding failure.

I did not create/run a fixture: an adversarial fixture could demonstrate that no run receipt is parsed, but cannot prove absence of actual human remeasurement. The code inspection above is decisive for the rule's observable contract. No fixture can distinguish “measured and then written” from “guessed and written” when both produce identical LOG bytes and the gate accepts no measurement receipt. This is explicitly a limitation of evidence, not an assertion about author intent.

## Shared correction paragraph: verdict

**Conditionally acceptable, not categorically forbidden.** A single measured run can legitimately correct multiple findings for the same script and oracle, and forcing one paragraph per finding would add ceremony without improving evidence. However, the implementation's paragraph-level aggregation permits accidental cross-binding: any citation, script mention, marker, and tally anywhere in the paragraph satisfy all findings whose observed number appears there. The wave-1 evidence demonstrates this shape on the live correction block: multiple listed findings share a paragraph and the gate does not test whether each finding's own line is cited (`CritC1Supersession.md:30-35, 162-180`). Therefore accept shared paragraphs only when each finding has its own explicit line citation in a well-defined correction entry and the measurement evidence covers the shared script/revision/tally. Different scripts or different oracle values need separately bound entries/receipts.

## Smallest safe rule sharpening

QUALITY criterion candidate: **A correction may supersede a tally only when its correction entry explicitly cites that finding's exact document line and binds the asserted tally to a successful independent measurement of the same script at the same measured revision (record command, revision, and machine-readable result/receipt); the gate must verify that receipt against its own oracle, not trust the paragraph's number.** Scope all text matching to one correction entry (bullet/item), not the whole paragraph. A multi-finding entry is permitted only if it explicitly lists every exact line and the one receipt applies to each; otherwise use separate entries. Keep the current oracle equality as a defense-in-depth check.

This is an improvement over merely requiring a fresh measurement claim in prose: prose itself is not independently verifiable. If producing/validating a receipt is outside current C1 scope, the minimal honest fallback is to label the correction text as an assertion, not proof of remeasurement, and make no calibration-quality claim from it. Do not silently treat “script + supersedes :N + number” as evidence that measurement occurred.

## Evidence discipline

No installs or upgrades. No fixtures, external requests, builds, linters, formatters, tracked-file edits, or git writes. Evidence consists of the cited source/claim and wave-1 report reads; no new numerical measurements are claimed.
