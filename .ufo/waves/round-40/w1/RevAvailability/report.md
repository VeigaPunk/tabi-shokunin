## Findings

### High — successful but malformed/empty `ss` output is counted as a positive available observation
In `scripts/playwright-firefox-egress-round39.mjs:117-135`, round 40 returns unavailable only for `spawnSync` error or nonzero status. On status 0 it accepts arbitrary `stdout`, filters lines matching an owned `pid=...`, then returns `{ticks:1, ..., nonLoopback:0}` even if stdout is empty, header-only, or malformed. Thus an `ss` executable/wrapper returning exit 0 with empty or invalid output synthesizes positive ticks and zero egress. The counter’s `usable()` at `.ufo/waves/round-40/counters/c1-sample-span-v3.mjs:6` checks finite positive ticks and finite `nonLoopback`, not that the output represented a valid observation. Missing executable and ordinary nonzero exit are correctly unavailable (spawn error/status check); permission-denied/nonzero is likewise refused, but a successful empty/malformed response is not.

**Source-level falsifiers:** provide a controlled `ss` executable earlier in `PATH` that exits 0 with empty stdout, header-only output, and malformed rows; each must make both sample and final-sweep observations unavailable/refused (not `ticks:1`). Also test a nonzero exit and absent executable to retain fail-closed behavior. Keep these as isolated tests of observation parsing; do not loosen C1’s predicate.

### High — `/proc` files can be malformed/empty and still produce positive ticks; individual fd permission/readlink failures are silently treated as no sockets
At `scripts/playwright-firefox-egress-round39.mjs:162-171`, `parseProcNet()` treats any readable file as parsed rows: it skips the first line, skips rows with fewer than 10 fields, and returns `[]` for empty/header-only/malformed content. `observeProc()` checks only null/unreadable at lines 205-208, so readable but invalid TCP/TCP6 data can produce `{ticks:1, inodes:0, nonLoopback:0}`. Worse, `socketInodesOfPid()` at lines 148-160 returns null only when listing `/proc/<pid>/fd` fails; individual `readlinkSync` failures are swallowed and omitted. `observeProc()` then skips a null PID at 211 and still returns positive ticks. A restricted `/proc` mount, hidepid/ptrace permissions, or per-FD races/access failures can therefore hide owned sockets without making the surface unavailable. Round 40 does correctly fail if either `/proc/net/tcp` or `/proc/net/tcp6` cannot be read (`nets.some(null)`), and if both are unavailable; this does not validate contents or each process’s fd coverage.

**Source-level falsifiers:** feed the parser readable empty/header-only, truncated, and malformed `/proc/net/tcp` and `tcp6` content and require unavailable/refusal; inject a `/proc/<owned-pid>/fd` enumeration/readlink permission failure and require unavailable/refusal rather than silently dropping evidence. Include an unreadable TCP6 file, unreadable TCP file, and both-unreadable cases. The current selftest only mutates receipt-level `{unavailable:true,ticks:0}` fields; it does not exercise these underlying observation/parser paths.
