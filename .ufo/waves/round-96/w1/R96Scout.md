## What the sources say against the frozen wording

- The wording "Puppeteer ... never resolves page.waitForFileChooser() for a chooser opened inside a cross-site iframe" is consistent with every Puppeteer source read (S-a, S-c): the only `Page.fileChooserOpened` listener and the only `Page.setInterceptFileChooserDialog` call sit on the primary client. No source read contradicts it. The "never" is a behaviour claim; only the live counter tests it, and only on Chromium 155 / 25.16.0 / localhost vs 127.0.0.1.
- Playwright's per-frame-session listener (S-i) supports "resolves for cross- and same-site children" at source level. Playwright's own tests do not exercise a cross-process iframe chooser (S-j). Its only evidence for the cross-site leg is the live run.
- No primary source found says Puppeteer 25.16.0 handles OOPIF file choosers. The release notes for the pinned version (S-d) show no such fix.
- The 2023 maintainer statement (S-f) matches the mechanism and the symptom, but is about a different version and reporter. It supports the direction, not the number or the Chromium 155 behaviour.
- Declared limit 3 (localhost vs 127.0.0.1 as "cross-site"): no source read addresses whether that pair is a separate site for Chromium's OOPIF decision. Not checked; left open for the L1.

## Risks and checks for the L1 (not run by me)

1. The C1 counter's cross-site Puppeteer legs require the raw witness event to carry an integer `backendNodeId` (S-b, S-l). If it did not, Puppeteer 25.16.0 would drop the event at line 477 and the timeout would look the same. The PPW receipt must show `backendNodeId` > 0; check that before admitting the mechanism sentence.
2. The Chromium-side per-session scope of `Page.setInterceptFileChooserDialog` is not documented (S-l) and the 155 implementation was not located (S-o). The claim already says the mechanism is "the source's account" (limit 5); keep it that way in any SOURCES row.
3. Playwright timing caveat (S-k): if any PWX/PWS leg ran `click` right after `setContent`, a missed event is possible. The counter's 3000 ms wait should absorb this, but a `--live` timeout on a Playwright leg needs this caveat before it is called a law finding.
4. Puppeteer #10017 (S-h) is open and not chooser-specific; do not cite it as proof that dialogs are unsupported on OOPIFs beyond "tracked as a gap".

## Verdict

No source opened contradicts the frozen C1 wording or its number. I did not run the counter, so no leg-level statement was tested by me. The evidence that bears on the claim is a source-level mechanism account plus a 2023 maintainer statement on an older version. The evidence for the behaviour remains the live receipts.
