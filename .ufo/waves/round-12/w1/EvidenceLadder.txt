3. CONTRADICTIONS & SUBSTITUTION TRAPS TO PREVENT
================================================================================
A. Trap 1: ARIA-as-Pixel Substitution (conflating ARIA snapshot / role locator with Visual Rendered State, Rungs 1 and 3)
- Contradiction: Conflating an ARIA snapshot match with visual rendering directly contradicts the measured findings in RT13 (D2/D8):
  1. Off-screen or hidden elements: Elements with `.sr-only` (`clip: rect(0,0,0,0); position: absolute; width: 1px; height: 1px; overflow: hidden`), `opacity: 0`, or covered by opaque overlays remain in the accessibility tree and match `getByRole` or `toMatchAriaSnapshot`, but render ZERO visible pixels to the user.
  2. Presentational elements: Elements with `role="presentation"`, `role="none"`, or styled text without semantic wrappers are stripped from the accessibility tree, yet are fully visible on screen.
  3. Visual defects: Color contrast failures (WCAG 1.4.3), missing font glyphs, broken layouts, and clipped text boxes are invisible to ARIA snapshots.
- Hard Invariant: An ARIA snapshot match NEVER proves "the page renders X" or "X is visually displayed". It can never substitute for Rung 1 static PNG bytes or Rung 3 visual screenshot read-back.

B. Trap 2: ARIA-as-Network Substitution (conflating locator auto-waiting / ARIA match with Wire Truth, Rung 4)
- Contradiction: Conflating locator presence or snapshot updates with network completion contradicts measured cases D4, D6, and D7:
  1. Client-side mutations: A locator can resolve or an ARIA snapshot can update via client-side JavaScript state, optimistic UI updates, or in-memory caches without issuing any network request (D6 cache-served repeats have 0 wire lines).
  2. Failed/aborted requests: An interaction can fail on the wire (D4 client abort, HTTP 500/502/504) while leaving the pre-existing DOM/AX tree intact, or conversely, an API request can succeed (200 OK) while the client fails to render the resulting semantic elements.
  3. Network timing & body bytes: Locators provide zero insight into transferred byte closure (`finEnc`), headers (`responseReceivedExtraInfo`), or wire latency.
- Hard Invariant: An ARIA snapshot or locator assertion NEVER proves "the page fetched X / got Y / got nothing". It can never substitute for Rung 4 wire capture.

C. Trap 3: Semantics-as-Audit Substitution (conflating role presence with accessibility conformance)
- Contradiction: Declaring `<div role="button">Submit</div>` matches `getByRole('button', { name: 'Submit' })` and satisfies an ARIA snapshot `- button "Submit"`, but completely fails keyboard operation (`Enter`/`Space`), focus management (`tabindex="0"`), and WCAG 2.1/2.2 conformance.
- Hard Invariant: ARIA locators and snapshots reflect semantic metadata exposed to the browser's accessibility tree, never full accessibility or WCAG compliance.

4. PROPOSED MOVE: THE SEMANTIC-LAYER ROUTING ADDENDUM (Bounded Synthesis)
================================================================================
Without adding a 5th rung (which would violate the 4-rung ceiling earned in round 4 and maintained through round 11), synthesize a formal Semantic-Layer Routing Addendum in the round-12 knowledge note and SKILL layer routing:

1. Position ARIA Snapshots as Layer L6.5 in the Layer Routing Table:
   - L6: DOM Document Content (CDP `DOMSnapshot` columnar arrays + shape text; captures all elements, text nodes, `::marker` pseudo-elements, and raw input values with `-1` sentinel).
   - L6.5: Computed Accessibility Tree (Playwright ARIA Snapshots; YAML representation of computed roles, accessible names via AccName, and ARIA attributes; filters presentational noise; supports partial matching and strict `/children` constraints).
   - L7: Pixels (Screenshot PNG + pixel tools; visible rendered state; only layer seeing `display:none` and `:visited`).

2. Precise Ladder Rung Connections:
   - Rung 1 (Static bytes): DISALLOWED for ARIA snapshots. Rung 1 requires pixel-level image determinism. ARIA is blind to styling, colors, and layout.
   - Rung 2 (Dynamic capture): ALLOWED as action targeting and wait predicates (`page.getByRole(...)`), NOT the outcome evidence. The effect of the action must be captured in the appropriate before/after artifact (L6.5 ARIA YAML, L6 DOM, L7 PNG, or L4 wire slice).
   - Rung 3 (Multi-signal): ADMITTED as a distinct third structural channel. Solves the historical r3 debt (`executor-test-sufficiency.md:95`) where Rung 3 lacked a second independent structural channel beyond DOMSnapshot. An action-effect claim achieves maximized multi-signal corroboration when Visual (L7 PNG), Raw DOM (L6 DOMSnapshot), and Semantic Structure (L6.5 ARIA Snapshot) all independently agree.
   - Rung 4 (Network wire): STRICTLY DISALLOWED for ARIA. Wire truth must be arbitrated by CDP Network events, ExtraInfo, and server logs.

3. Two Immutable Anti-Substitution Rules for C2 Note:
   - Rule A (Anti-Pixel): "An ARIA snapshot match proves only that the browser's accessibility engine computed the specified roles and names; it cannot prove visual visibility, layout stability, or pixel rendering. Any visibility claim must pair with Layer L7 (screenshot)."
   - Rule B (Anti-Network): "An ARIA locator resolution proves only that an element matching the semantic query was attached to the client DOM at the moment of evaluation; it cannot prove that a network request was dispatched, reached the wire, or completed. Any traffic claim must pair with Layer L4 (CDP Network slice)."
