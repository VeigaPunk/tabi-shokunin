## 3. Core Mechanics Breakdown

### A. Role and Name Selection (`page.getByRole(role, options)`)
- **Implicit & Explicit Role Resolution**: Playwright maps native HTML tags (`<button>`, `<a href>`, `<input type="checkbox">`, `<h1>`-`<h6>`, `<ul>`, `<li>`, etc.) to standard ARIA roles according to W3C HTML-AAM mapping, as well as explicit `role="..."` attributes.
- **Name Resolution (`options.name`)**: Matches the element's accessible name computed according to the W3C Accessible Name and Description Computation (AccName) specification.
  - Substring match by default, case-insensitive.
  - Supports regular expressions (e.g. `getByRole('button', { name: /submit/i })`).
  - Supports `exact: true` (case-sensitive, whole-string, but trims leading/trailing whitespace).
- **Filtering by ARIA State**:
  - `checked`: boolean (matches `aria-checked` or `<input type="checkbox">` state).
  - `disabled`: boolean (inherits through DOM hierarchy; matches `aria-disabled` or native `disabled`).
  - `expanded`: boolean (matches `aria-expanded`).
  - `level`: number (heading level `<h1>-<h6>` or `aria-level`).
  - `pressed`: boolean (matches `aria-pressed`).
  - `selected`: boolean (matches `aria-selected`).
  - `description`: string | RegExp (matches accessible description via AccName; added in v1.60).
  - `includeHidden`: boolean (defaults to `false`, adhering to ARIA tree exclusion rules).

### B. Strictness Mechanics
- **Single-Element Operations Enforce Strictness**: Any interaction or single-element assertion (`click()`, `fill()`, `hover()`, `check()`, `textContent()`, `toBeVisible()`) expects exactly one DOM element matching the locator expression. If `matches.length > 1`, Playwright throws a strict mode violation error immediately rather than picking an arbitrary element.
- **Multi-Element Operations Permit Multiplicity**: Methods like `.count()`, `.all()`, `.evaluateAll()` explicitly accept zero, one, or multiple matches without error.
- **Opt-Out Primitives**: `.first()`, `.last()`, `.nth(i)` explicitly bypass the strictness check by indexing into the match set.
  - **Risk**: Fragile against layout updates and async re-renders. If matching elements shift order, actions execute on an unintended element without warning. Playwright officially marks these as "not recommended" for disambiguation.
- **Recommended Disambiguation**: Use `.filter({ hasText: ... })`, `.filter({ has: locator })`, or `.and(locator)` / `.within(container)` rather than numeric indexing.

### C. Label Locators (`page.getByLabel(text, options)`)
- **Scope**: Designed specifically for form fields / inputs.
- **Resolution Mechanisms**:
  1. Associated `<label for="id">` matching `<input id="id">`.
  2. Wrapping `<label>Label Text <input /></label>`.
  3. `aria-labelledby="labelId"` pointing to element text.
  4. Explicit `aria-label="Label Text"`.
- **Options**: `exact: boolean` (case-sensitive, full string match, whitespace-trimmed).

## 4. Potential Overclaims & Boundary Hazards (Inferences & Warnings)

1. **Overclaim: Role locators ensure accessibility compliance (False)**
   - *Evidence*: Playwright documentation explicitly warns that role locators "do not replace accessibility audits and conformance tests".
   - *Boundary*: A page can pass Playwright `getByRole` selectors while having severe WCAG violations (e.g., poor color contrast, broken tab order, lack of keyboard focus indicators, screen reader traps, or nonsensical role abuse).

2. **Overclaim: Role locators work without accessible names (Hazard)**
   - *Evidence*: In real applications, multiple buttons, links, or inputs exist on a single view. Omitting `{ name: '...' }` almost invariably triggers strictness violation errors. Locating by bare role alone is only viable for unique landmark roles (`main`, `banner`) or inside strictly scoped subtrees.

3. **Overclaim: Role locators verify visual rendering (False)**
   - *Evidence*: Role locators query the DOM accessibility tree and computed accessible properties. An element obscured by another transparent element or styled with zero opacity might still exist in the accessible tree unless properly hidden via `aria-hidden="true"`, `display: none`, or `visibility: hidden`.

4. **Overclaim: `first()` or `nth()` is a safe disambiguation strategy (Hazard)**
   - *Evidence*: Playwright documentation explicitly warns against `.first()`, `.last()`, and `.nth()` as a substitute for proper locators. Ordering in the DOM is unstable across dynamic component updates, leading to silent wrong-element interaction flakiness.

5. **Overclaim: `getByLabel` works for general content (False)**
   - *Evidence*: `getByLabel` targets form control inputs associated with a label, not general static text, headings, or structural container elements.
