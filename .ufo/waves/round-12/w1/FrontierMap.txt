3. QUEUED ACCESSIBLE-SELECTOR SURFACE (S023–S025 ANALYSIS)
================================================================================
The queued ground is specified by three Tier-A rows in `corpus/SOURCES.md:37-39`:

1. S023: `https://playwright.dev/docs/locators` (Playwright Locators)
   - Scope: Role, label, text selector semantics.
   - Anchor: §Locate by role, §Locate by label, §Strictness.
   - Teaches: Role locators reflect user and assistive-technology perception (buttons, checkboxes, headings, links, etc.) following W3C specifications for ARIA role, ARIA attributes, and accessible name.
   - Critical Invariant 1: Locators are strict by default—operations throw if >1 element matches.
   - Critical Invariant 2 (Audit Boundary): Role locators are explicitly NOT an accessibility audit or WCAG conformance test; they test page perception for interaction.

2. S024: `https://playwright.dev/docs/aria-snapshots` (Playwright ARIA Snapshots)
   - Scope: ARIA snapshot representation and matching (`toMatchAriaSnapshot`).
   - Anchor: §Aria snapshots, §Partial matching.
   - Teaches: An ARIA snapshot is a YAML-formatted accessibility-tree template. It represents accessible roles, names, and hierarchical structure.
   - Nature: Structural evidence, not pixel/screenshot diffing and not raw Chromium DOM tree dumps. Supports exact or partial subtree matching.

3. S025: `https://www.w3.org/WAI/ARIA/apg/` (W3C ARIA Authoring Practices Guide)
   - Scope: Canonical authoring practices, accessible widget patterns, role/name semantics.
   - Anchor: APG home, widget patterns.
   - Teaches: Normative grounding for which roles, states, properties, and keyboard patterns an element/widget must expose to assistive technologies before asserting it by role.

Study Path (`corpus/SOURCES.md:49`):
- `accessible-selectors (queued, not mined) — S025 → S023 → S024`: Semantic roles and names first (S025), then role locators (S023), then ARIA snapshots as structural evidence (S024).

To prevent redundant documentation and preserve signal, the new admission must strictly distinguish between what the corpus already holds and what S023–S025 uniquely add.

A. Already Held Knowledge (DO NOT DUPLICATE AS NOVELTY):
1. CDP Columnar DOM Snapshot (`knowledge/cdp-evidence-patterns.md:77`, `knowledge/multi-step-journey.md:148-151`):
   - Tabi already holds `DOMSnapshot.captureSnapshot` ({computedStyles:[]}), which returns raw Chromium parallel columnar arrays (`attributes`, `backendNodeId`, `isClickable`, `nodeName`, `nodeValue`, `parentIndex`, `strings` table) and parses input values with the `-1` empty sentinel.
2. WebBridge `@e` Accessibility Refs (`knowledge/webbridge-plugin-anatomy.md:81-83,109-111`):
   - Tabi already documents Kimi WebBridge's high-level `snapshot` tool, which emits an accessibility tree with ephemeral `@e` reference identifiers (`@e1`, `@e2`), and holds the policy preferring `@e` refs over raw CSS/JS.
3. Layer-Routing Disagreement Ladder (`knowledge/layer-routing-synthesis.md:57-58,83-84`):
   - Tabi already separates Rung L6 (DOM: document content incl. invisible nodes via DOMSnapshot) from Rung L7 (Pixels: visible rendered state via screenshot PNG, seeing `display:none` and `:visited`).
4. Actionability Checks vs Post-Action State Predicates (`knowledge/web-flake-retry-evidence.md:70-79`):
   - Tabi already mined S015 (Auto-waiting/actionability) and S016 (Auto-retrying assertions) to prove that action prerequisites (visible, stable, enabled) are distinct from test state predicates.
5. BiDi Node Locator Mapping (`knowledge/webdriver-bidi-capability-matrix.md:64`):
   - Already mapped CDP `DOMSnapshot` vs BiDi `browsingContext.locateNodes`.
6. Host Runtime Perimeter:
   - Tabi runs standalone Chromium directly via raw CDP loopback scripts (`SKILL.md:127-140`). NO Playwright runner, test runner, or browser automation library is installed or run on the host.

B. Genuinely New Ground (THE UNIQUE ADDITION OF C2):
1. User-Facing Semantic Role/Name Selection:
   - Moves selector discipline from tag/class/DOM-path or opaque `@e` tokens to standard accessible semantics (`role`, `accessible name`).
2. YAML ARIA Snapshot Representation as a Distinct Evidence Substrate:
   - An ARIA snapshot represents the accessible tree as human-readable, machine-matchable YAML templates (`- role "name"`).
   - It bridges the gap between brittle raw DOM structures (affected by extraneous wrapping divs/styles) and brittle pixel screenshots (affected by fonts/GPU rendering/antialiasing).
3. Locator Strictness as an Anti-Ambiguity Invariant:
   - Documents the contract where selectors fail closed if ambiguous (>1 matching target), preventing non-deterministic target interaction.
4. Formal Demarcation of Semantic Location vs Accessibility Conformance:
   - Establishes that passing role/name locators or ARIA snapshot matching does NOT constitute an accessibility audit or WCAG conformance proof.
