## 3. Chrome for Testing (CfT) Exemption Mechanism

- Stated Unknown in Note:
  - Note §3 row 5: "| Chrome for Testing | any | blog-claimed exempt (S001); mechanism not found in this file — [unknown] |"
  - Note Unknowns #2: "Chrome for Testing's exemption mechanism — not located in remote_debugging_server.cc; blog claim only."
- Resolution of the Exemption Mechanism via Build-System Architecture:
  1. In the Chromium GN build system (build/config/chrome_build.gni), Chrome for Testing is defined by is_chrome_for_testing = true.
  2. chrome_build.gni enforces mutual exclusion:
     assert(!is_chrome_for_testing || !is_chrome_branded,
            "`is_chrome_for_testing` is incompatible with `is_chrome_branded`")
  3. The preprocessor flag GOOGLE_CHROME_BRANDING is defined solely by is_chrome_branded = true (build/BUILD.gn).
  4. Because is_chrome_for_testing mandates is_chrome_branded = false, BUILDFLAG(GOOGLE_CHROME_BRANDING) evaluates to 0 in all Chrome for Testing builds.
  5. Consequently, in remote_debugging_server.cc, Chrome for Testing falls directly into the #else branch where default_user_data_dir_check_enabled defaults to false.
  6. No CfT-specific macro or branch exists inside remote_debugging_server.cc because CfT is structurally an unbranded build variant at the compiler preprocessor level.
  7. Additionally, S001's stated motivation for the boundary is protecting App-Bound Encryption keys on consumer Chrome; CfT does not use consumer profile encryption or consumer default profiles (docs/chrome_for_testing/README.md).
- Status: The mechanism is now fully accounted for at the GN build and preprocessor level (incompatible with is_chrome_branded), explaining why no CfT-specific code appears in remote_debugging_server.cc. However, as an empirical runtime fact, it remains unexecuted/unobserved locally.
