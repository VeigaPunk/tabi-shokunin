== F1 (HIGH, false provenance) — "not pixels" is a curator gloss, not S024 text ==
Claim under attack: corpus/SOURCES.md:38 says "structural evidence, not pixels"; SKILL.md:1637 says "An ARIA snapshot replaces neither pixels…".
Evidence: the extracted S024 body text has zero matches for "pixel". "screenshot" and "visual" appear only in the site nav and in the codegen tab description ("visually represents the aria snapshot"). S024 says: "A template is a constraint, not necessarily a complete serialization of the accessibility tree." (§Aria snapshots).
Counterexample: U-a, locator.ariaSnapshot option `boxes` (Added in v1.60): "appends each element's bounding box as [box=x,y,width,height] … in CSS pixels". ariaSnapshotJSON (v1.63) has the same option. A snapshot can therefore carry layout geometry. Rendered appearance (color, contrast, overlap, clipping, paint) is still absent. That absence is an [inference]: the representation lists roles, names, attributes, text and /url only (S024 §Aria snapshots).
Axes: provenance, calibration.
Smallest correction: the entry must label "not pixels" as [inference] from S024's representation list, not as a quote. It should also add: "`boxes` (v1.60+) adds viewport geometry, not rendered pixels; a boxes-bearing snapshot is DPR/viewport-dependent." Optionally amend the S024 gloss in SOURCES (L1-owned) to "structural; no rendered appearance".

== F2 (HIGH, hidden state) — S024 says nothing about hidden elements; three visibility notions diverge ==
Evidence:
- S024 has zero matches for "hidden", "aria-hidden", "shadow", "iframe" or "frame" outside the nav. [observation] Whether hidden or aria-hidden nodes appear in a snapshot is UNKNOWN from S024.
- U-a getByRole `includeHidden`: "By default, only non-hidden elements, as defined by ARIA, are matched by role selector."
- S023 §visible(): `<button style='display: none'>Invisible</button><button>Visible</button>`. page.locator('button') "will find both buttons and throw a strictness violation error".
- SKILL.md:395: "DOM shape is blind to `display:none` and `:visited`"; "screenshot is the only rendered-state layer".
Counterexamples [inference; not run]:
- An aria-hidden="true" element that is painted. It is absent from role matching by default (U-a) but present in pixels.
- A visually-clipped or off-screen labelled control. It is present for role matching but absent from pixels.
- A CSS locator over a display:none node. It is present in DOM shape and absent from both other channels.
So "snapshot matched" ≠ "user sees it" ≠ "DOM has it".
Axes: correctness, calibration.
Smallest correction: the entry adds a 3-column visibility table: DOM presence / ARIA-hidden-filtered / rendered. Each cell cites S023, U-a or SKILL.md:395. "Snapshot includes/excludes hidden nodes" is marked UNKNOWN (S024 silent) until a pinned local probe exists.

== F3 (HIGH, semantic equivalence) — a passing template is much weaker than "tree equals" ==
S024 rules that each allow a pass the reader may not expect:
(a) Omitted attributes and names: "the checked attribute is ignored, so the test will pass regardless of the checkbox state". An unnamed `- button` passes "regardless of the button's label".
(b) Default /children `contain`: "Matches if all specified children are present in order". "With no expected child entries, contain allows any children".
(c) Location: "A single-node template can match at any depth within the selected page or locator." `- button "Submit"` scoped to page passes on ANY Submit button, including one in the wrong region.
(d) Regex names and /url: `- heading /Issues \d+/`, `/url: /https://…/.*/`.
(e) Comparison "normalizes whitespace within names and text values".
(f) `equal`/`deep-equal` constrain children only. S024 never states that deep-equal enforces omitted attributes or names → UNKNOWN. "Strict" matching is therefore child-list strictness, not full-node equality.
(g) U-a `depth` option (v1.59) truncates the generated snapshot. The default-mode snapshot excludes iframe content. That is an [inference] from U-a: ai mode "Includes snapshots of <iframe>s inside the target" is listed as a difference from default.
SKILL.md:1636 states (a) and (b) and "not full-tree equality". It omits (c), (d), (f) and (g).
Axes: correctness, calibration.
Smallest correction: the entry's receipt contract requires recording scope locator, children mode, depth, mode (default/ai), boxes flag, and every regex used. (c) and (f) become explicit pitfalls; (f) is marked UNKNOWN.

== F4 (MED, hidden temporal state) — the assertion retries, so a pass hides intermediate states ==
Evidence: S024 §Updating snapshots: "Playwright retries the assertion until its expect timeout expires." Tabi's own flake note already separates actionability from the state predicate (web-flake-retry-evidence.md:76-80).
Counterexample [inference]: a page passes through a broken accessible state (e.g. "button" briefly unnamed). Then it reaches the template state before timeout. toMatchAriaSnapshot passes, and the transient is never recorded.
Smallest correction: the entry says a toMatchAriaSnapshot pass is an eventually-true predicate, not a first-observation capture. It is not ladder rung-2 before/after evidence unless paired with the SKILL.md:372 state-wait capture.

== F7 (HIGH, semantics ≠ behavior; S025 over-reach) ==
Evidence:

- U-e Read Me First: "A role is a promise … the author … has also incorporated JavaScript that provides the keyboard interactions expected for a button. Unlike HTML input elements, ARIA roles do not cause browsers to provide keyboard behaviors or styling."

Also: the S025 gloss "Which roles, names and keyboard patterns a widget should expose" (SOURCES.md:39) is not supported by the opened home page.

The "role is a promise / keyboard not proven" boundary is either cited via a new APG Read-Me-First row (L1-owned SOURCES change) or kept as a labelled unregistered lead. == F9 (MED, ladder independence) — can a snapshot be a rung-3 "independent signal"? ==
Evidence: SKILL.md:373 rung 3 requires "two or more independent signals agree" (screenshot, DOM shape, protocol metadata). An accessibility tree is derived from the same DOM+style that DOM-shape captures [inference]. Agreement with DOM-shape is therefore correlated, not independent.
SKILL.md:1637 says a snapshot "replaces neither pixels nor network/state evidence". That bars substitution but does not bar counting the snapshot as an extra rung-3 vote.
The converse is also missing: a passing screenshot or DOM-shape capture says nothing about accessible names or roles. A visually perfect div-button has no role.
Smallest correction: add to SKILL.md:1637's boundary (L1): "a snapshot adds an accessible-semantics channel; it is not independent of DOM shape for rung 3, and pixels/DOM do not establish accessible semantics."
Separately, SKILL.md:1637 "state evidence" is ambiguous, because snapshots do carry ARIA states (checked/expanded/pressed, S024). It should say "the ladder's DOM state predicate".
