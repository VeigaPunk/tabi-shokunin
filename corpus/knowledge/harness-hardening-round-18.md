# Hardening a CDP/Playwright evidence harness

This note states the hardening contract for the round-18 WebMCP evidence harness, the hazards it closes, and the finite probes that test each closure. It records no measured counts. Observed counts come only from the committed `measurements.json` of the C2 measurement run (`node .ufo/waves/round-18/measure-c2.mjs REV`), and a reader must take them from that file, not from this prose.

Hazard sources are the round-17 harness `scripts/webmcp-invoke-round17.mjs` (byte-frozen; line numbers below refer to it) and the wave-1 probe report `.ufo/waves/round-17/w2/SentinelHarnessAfter.md`.

## Documented contract (what each source states)

- **Signals (S059, S063).** Playwright's `launch` and `launchPersistentContext` default `handleSIGINT`, `handleSIGTERM` and `handleSIGHUP` to `true`; each means "close the browser process" on that signal. Node's default for `SIGTERM` and `SIGINT` is to exit with `128 + signal number`. Installing a listener for one of these signals removes that default exit (`doc/api/process.md:757-759`). `SIGKILL` and `SIGSTOP` cannot have a listener (`:778-780`). `process.exit()` can drop output that has no completed write, because pipes and sockets are asynchronous on POSIX (`:4228-4247`). The v24.22.0 page adds that signal events may run after Node has exited when the loop is empty (S063, §Signal events, latest page); the v24.21.0 tag does not carry that sentence.
- **Arguments (S059).** `args` is added to Playwright's own switches. `ignoreDefaultArgs: true` replaces them and is documented as dangerous. Playwright rejects a caller-supplied `--user-data-dir` and a caller-supplied `--remote-debugging-pipe`; these throws are in `coreBundle.js` near line 44750.
- **Pipe transport (S061, S062).** `BrowserContext.newCDPSession(page)` returns a raw CDP session and is documented as Chromium-only. For a launched Chromium, Playwright's default launch adds `--remote-debugging-pipe` (`chromium.ts:355-358`) and uses the stdio pipe on fds 3 and 4 (`browserType.ts:274-278`). `newCDPSession` sends `Target.attachToTarget` over that same connection (`crBrowser.ts:606-620`). The pipe switch by itself starts no HTTP listener (`remote_debugging_server.cc:353-361`). `--remote-debugging-port` is a separate switch that does start one, and the guard comment at `:397-400` names both flags, so a launch can carry both; whether one launch with both starts both servers is [INFERENCE] until the `h3` argv probe observes it. `DevToolsActivePort` is written only by the HTTP handler, and only when the output directory is non-empty (`devtools_http_handler.cc:297-306`).
- **Downloads (S060).** `acceptDownloads` defaults to accept. `false` maps to an internal `deny` (`coreBundle.js`, `toAcceptDownloadsProtocol`), and Playwright's `Download` object is documented to report a refused download through `failure()`. [INFERENCE] that the refusal reaches the page-level `download` event under `deny` with events enabled is read from the 1.64.0 client path; the `h4` run is the observation that settles it. Playwright's own `playwright-artifacts-*` directory is created under `os.tmpdir()` unless `artifactsDir` is set.
- **Switch merge (S064).** Chromium keeps one value per switch name. A later `--enable-features=` replaces an earlier one, and the earlier list is dropped whole. Each list is comma-split. For a feature named in both lists, disable wins (`feature_list.cc:449-453`). The `argv` still shows both tokens, so counting tokens in `/proc` argv is the correct probe.

## Finite probes (`.ufo/waves/round-18/measure-c2.mjs`)

The counter runs in a sandbox clone at REV and at B. Each probe uses a fresh TMPDIR and reports pass or fail with its evidence string. The counter also carries negative controls, so a probe that is always green fails its self-test. This note gives the control shapes only and does not quote exact control IDs: the committed counter run lists its own IDs. The shapes are: a synthetic signal handler that exits with the wrong code (must fail `h1`); a leftover file in TMPDIR after exit (must fail `h2`); a browser argv carrying a remote-debugging port (must fail `h3`); a download that is not refused (must fail `h4`); a duplicate feature switch (must fail `s1`); a poisoned `HEAD` accepted by the wrapper (must fail `f6`); and a coverage-retention gate that rejects a receipt without full coverage. The counts are in the committed `measurements.json`; this section names the checks only.

## Rules that follow

1. One exit path: every exit (normal, signal, watchdog, thrown error, `failStart`) calls the same idempotent cleanup, and a signal is `run_aborted`, never a product `fail`.
2. Browser output lives under the run: browser and Node TMPDIR both point inside the run directory.
3. No TCP DevTools port: CDP runs over `context.newCDPSession(page)` on Playwright's pipe.
4. Downloads are refused and recorded: a download is a finding, not bytes on disk.
5. One switch per name: one merged `--enable-features=` and at most one `--disable-features=`, asserted per launch.

## Bounds (what these claims do not establish)

- **The pipe is not wire bytes.** The `--remote-debugging-pipe` transport carries CDP JSON on fds 3 and 4. The harness records the messages that `CDPSession.send` and `session.on('event')` deliver, not a capture of the bytes on the pipe. "Verbatim" in the receipt means the session-level message, not the raw wire.
- **The wrapper is a guarded entry point, not a gate.** `scripts/freshness-witness.mjs` resolves the lane tip by default and refuses `HEAD`, symbolic names, short or dash-led revisions, and explicit revisions that are not ancestors of `refs/heads/master`; its own fixture tests cover these refusals. It does not stop a direct call to the byte-frozen `scripts/check-freshness.mjs --witness <40-hex>`, which remains bypassable by any caller.
- **A download failure event is not proof of no disk bytes.** `acceptDownloads: false` produces a `download` event with a `failure` value. That event shows Playwright's view. The absence of bytes on disk is shown only by the `h4` TMPDIR scan, which is itself limited to the run's TMPDIR and to the suggested filename.
- **Historical F6 witnesses are explicit strict ancestors, not inherited values.** The wrapper accepts an explicit `--rev` only as a 40-hex value that `git merge-base --is-ancestor` confirms is an ancestor of `refs/heads/master`; the default is the lane tip. Symbolic names, `HEAD`, short hashes and off-branch hashes are refused. A historical witness is therefore an intentional explicit ancestor. A descendant or inherited value is accepted only when it is itself passed as a strict 40-hex value and passes the same ancestor check; containment and names are never used.
- **BiDi launch is out of scope.** `coreBundle.js` near line 44936 has a `--remote-debugging-port=0` default in the WebDriver BiDi launcher class (`BidiChromium`), which the harness does not use; the harness calls Playwright's default CDP `chromium` launcher, whose default is the pipe.
- **Not covered by this hardening:** argv allowlist (S3: `/etc/chromium-flags.conf` is read regardless of HOME, and no allowlist rejects `load-extension`, `proxy-server` or `no-sandbox`); network-namespace witness (S2: `loopbackOnly: true` and the WebSocket-deny claim are written unconditionally, and a swallowed `routeWebSocket` install failure is not recorded; the Sentinel's `unshare -rn` run had `lo` as the only interface, but the harness does not record that); field caps (S6: CDP frames, `output` and `exception` are stored without a cap, and ledger POSTs have no count limit); and `NODE_PATH` and entry identity (S8: the harness still searches `NODE_PATH`, and the version check reads only `package.json`).
- **Scope of the claim.** The round-17 harness stays byte-frozen as a counted input. The round-18 harness is `scripts/webmcp-invoke-round18.mjs`. This note claims no real-site run, no agent-side invocation, no default-profile run, and no Chromium version beyond 154.0.8037.97.
- **Playwright default switch list.** S059 does not enumerate Playwright's default Chromium switches, so the S1 merged list is grounded by the effective-argv audit, not by the docs.

## Wave-2 clarifications and corrections

- Source-backed default facts and tabi design rules are different. “Must own shutdown” and
  “record both events” are derived evidence policies, not quoted API mandates. S070 supersedes
  S063's attribution. S059's full launch-option locations are in its dossier: signals1221-1234,
  args1182-1190 and ignoreDefaultArgs247-253 at Playwright1.64.0; S061's source paths and transport
  boundary are in its dossier, including client-side synthesized request IDs.
- The §Documented contract wording “signal events may run after Node has exited” was wrong.
  Node24.22's actual clarification says Node may exit **before the listener is called if the
  event loop is otherwise empty**; it does not describe events executing in an exited process.
  That later version is not S070's24.21 source. The pinned fact remains listener-removes-default.
- The counter prints JSON to stdout; it does not create `measurements.json`. The L1 captures
  argv, exit, full output and producer identities in
  `corpus/evidence/round-18/measurements.json`, which is the final measurement pointer. The
  initial integration did not yet contain that file; the older present-tense pointer was premature.
- CDPSession error entries are constructed from actual `session.send` rejections, not observed
  wire error frames. Numeric protocol codes remain unavailable; the functional negative controls
  retain protocol failure/no-invocation meaning with the missing numeric facet explicitly bounded.
- Dropping the port applies only to this harness; it neither rules the four contested CDP rows
  nor manages Chromium/Playwright/sibling tools. The frozen direct freshness CLI is still bypassable.
- Superseding S071 narrows the old SKILL1956 and round17 invocation-note54/73 schema statement
