If you want command input to still be interpreted as usual by git rev-parse before the output is shell quoted, see the --sq option. Example $ cat >your-git-script.sh <<\EOF #!/bin/sh args=$(git rev-parse --sq-quote "$@") # quote user-supplied arguments command="git frotz -n24 $args" # and use it inside a handcrafted # command line eval "$command" EOF $ sh your-git-script.sh "a b'c" EXAMPLES Print the object name of the current commit: $ git rev-parse --verify HEAD Print the commit object name from the revision in the $REV shell variable: $ git rev-parse --verify --end-of-options $REV^{commit} This will error out if $REV is empty or not a valid revision. Similar to above: $ git rev-parse --default master --verify --end-of-options $REV but if $REV is empty, the commit object name from master will be printed.
